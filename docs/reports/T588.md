# T588 — Corrected literal-signature audit of the five non-slot-2 inputs

## Verdict

This report supersedes `docs/reports/T583.md`.

At repository commit `4a7a96507b8ecdded7bd043f345eac8d41d7bb14`, the five inputs other than
the A-prime slot are **not** a dispatch-ready family of universal Gaussian producers for
`RBM.Slot'.thm221NoEL_of_inputs_mergedOnAll_aprime'` or
`RBM.APrimeModel.thm221NoEL_of_inputs_mergedOnAll_aprime`.

|---|---|---|
| `Step1.Hyp` | Gaussian mathematics **produced**, exact generic A-prime argument **not directly inhabited** | `RBM.Gauss.step1Hyp_slot` produces `Step1.Hyp (Gauss.sample d) E s t` from the left `BoundsCore`; the generic A-prime `h1` parameter is asked before and without that `BoundsCore` |
| `CutHypEvOnSlot` | **missing** | only an adapter from an already complete `CutHypEv` is present; no producer for the actual `xiLK ... 2` modulus and truncated moments was found |

these five being the actual Gaussian `CutHypEvOnSlot` package**.  There is also a separate Step-1

received the left `BoundsCore`.

This report does **not** establish any universal slot, any six-step closure, Theorem 2.21, or the paper.

Four corrections to T583 are essential:

1. `d` has type `Gauss.Dims`, not `Data`.
2. `s,t` have type `Nat -> Real`; `hs0`, `hst`, and `ht1` are pointwise in `N`.
3. `Cond272Reg` is attached to `Gauss.band d`, not `Gauss.sample d`.
4. `Step1.Hyp` has no `c` argument.  The number `c` occurs only in the prefix through

The order is not cosmetic: `APrimeSlotFields.lean:679-684` applies the five functions exactly in this
order, and passes the step's `hB` only to `hcut`, not to `h1`.

Write `A_u = W ell_u eta_u`.  The visually checked formulas are:

| (2.76) | `|L_u-K_u| prec (eta_s/eta_u)^4 A_u^(-2) exp(-sqrt(|a1-a2|/ell_u)) + W^(-D)` |
| (2.77) | `max |L_u| prec A_u^(-n+1)` |
| (2.78) | `max |L_u-K_u| prec A_u^(-n)` |

| (2.80) | `max |E L_u-K_u| prec A_t^(-3)`, for `s <= u <= t` |

In particular, (2.76) has the fourth power of the time loss, (2.79) removes that loss, and (2.80)
uses the endpoint scale `t`, not `u`.  The five Lean inputs are internal packages used to reach these
steps; they are not in one-to-one correspondence with five displayed formulas.

The paper states Theorem 2.21 for `t > s`.  The Lean consumers ask the pointwise weak inequality
`s N <= t N`, hence also include collapsed windows.  More importantly, they include the positive-length
first grid cell with left endpoint `s = 0`, and their interval types use both closed endpoints.  A
universal producer must handle all of these cases; a proof only for `0 < s`, only for one endpoint, or
only for `s=t` does not dispatch.

## Input 1: `Step1.Hyp`

### Literal producer

`RBM.Gauss.step1Hyp_slot` has the exact type

```lean
(d : Dims) -> 0 < kappa ->
forall E, |E| <= 2 - kappa ->
forall s t : Nat -> Real,
  (forall N, 0 <= s N) ->
  (forall N, s N <= t N) ->
  (forall N, t N < 1) ->
forall c, 0 < c -> Cond272Reg (band d) E s t c ->
  BoundsCore (sample d) E s ->
  Step1.Hyp (sample d) E s t.
```

Thus the Step-1 mathematics is produced from the natural left induction hypothesis and has the correct
(2.73)-(2.74) target scales.  It does not use a later step and is acyclic.  The repository also contains
an unconditional positive-length first-grid-cell witness, so this implication is not vacuous.

### Exact A-prime mismatch

The generic A-prime consumers ask `h1` without a `BoundsCore` antecedent.  Therefore
`step1Hyp_slot d hκ0` is **not** a term of their `h1` type.  The older Gaussian-specialized merged
wrapper (`Step345Producer.lean:1132-1155`) demonstrates the correct integration pattern: it waits until
the step has `hB` and then calls `step1Hyp_slot` internally.  No analogous Gaussian-specialized A-prime
wrapper is present in the audited A-prime files.

**Classification:** the Gaussian Step-1 theorem itself passes; the exact generic A-prime `h1` argument
remains an integration mismatch.

## Input 2: `CutHypEvOnSlot`

### Literal content

`CutHypEvOnSlot (Gauss.sample d) E s t` existentially chooses one event `Good N`, requires it to be
measurable and `HighProb`, and requires a full

```lean
MomentDuhamelCut.CutHypEvOn
  (Gauss.band d).P
  (fun N u omega => (Gauss.sample d).xiLK E N u omega 2)
  s t
  (fun N => Step3.flowAs (Gauss.band d) E s N ^ (1/2 : Real))
  Good.
```

The underlying record requires positive truncation and mesh parameters, a single-event time modulus,
mesh fineness, polynomial net cardinality, measurability and nonnegativity, and the exact family of
truncated `2p` moments for every allowed `delta`, every `epsilon > 0`, and every `p`.  Its threshold is
`N^(2 delta) * flowAs(...,s)^(1/2)`.

`HighProb` rules out an eventually empty event in the probability model.  The consumer does not require
the cut event to equal the event used by `Eq548EntryDataEvOn'`; each package has its own event, and a
finite later intersection is legitimate.  What is required is one event inside this cut package for all
of its modulus uses.

### Search result

`cutHypEvOnSlot_of_cutHypEv` is only an adapter from an already complete unrestricted `CutHypEv`.
The generic `satCutHypEvOn` probe concerns a different toy functional.  The complete first-cell
`CutHypEvOn` declarations found elsewhere concern `jSfarSm`, not the required `xiLK ... 2` functional.
None proves the missing actual modulus and moment family.

The package may depend on the left `BoundsCore`, Step 1, and independently established slot-2 bounds.
It must not use (2.77), `Step3.Hyp`, or any equivalent sharp-loop conclusion, since this package is an
input to Step 3.

**Classification:** missing.  No nondegenerate Gaussian witness for the complete actual package was
found.

assume the desired sharp hierarchy under `SumZeroDyn.Hierarchy` or another synonym, because that would

## Input 5: `Eq548EntryDataEvOn'`

The exact old package existentially chooses one measurable `HighProb` event `Good` outside the internal
`D` quantifier.  On that same event it requires, for every `D > 0`, the entry modulus

```text
left side <= N^1 * |v-w|^(1/2).
```

It also requires the near estimate with time factor `(eta_s/eta_u)^2`, and the net moment family with
threshold `N^(2 delta)` and unit comparison scale.  The same `Good` must support all modulus instances;
`HighProb` excludes the empty-event shortcut.

This exact interface is not merely awaiting a proof.  `Thm221Assembly.lean:1231-1254` records the
compiled refutation of the hard-coded `(1,1/2)` modulus on the concrete `bandGrow` model for `D >= 2`,
and the structural jump obstruction for `Kmod <= 2 gamma`.  This does not by itself prove
`not Eq548EntryDataEvOn' (Gauss.sample d) ...` for every Gaussian `d`, so the safe conclusion is:

- the exact old proposition is invalid as a general model interface;
- no universal Gaussian producer for it is present;
- a constructor or adapter cannot cure the false modulus.

`Eq548EntryDataEvOnK'` repairs the statement by exposing `(Kmod,gamma)` and matching the net mesh; the
intended pair is `(D-1,1/2)`.  It is a different consumer type, and the declarations in the audited
file only transport supplied near/modulus/moment data.  They do not produce those data for the Gaussian
model.  A point-window modulus witness is degenerate and is not evidence for the required first cell.

**Classification:** the exact old slot fails; the repaired parametric slot remains conditional.

## Dependency and noncircularity audit

The safe proof order is:

```text
left BoundsCore + Cond272Reg
  -> Gaussian Step1.Hyp
  -> (2.73), (2.74)
  -> excluded slot 2: (2.75), (2.76)
  -> actual xiLK cut package + independent Lemma 5.14 inputs
  -> (2.77)
  -> independent (4.5) flow input
  -> (2.78)
  -> corrected, parameterized (5.48) entry package
  -> (2.79)
  -> (2.80).
```

Consequently:

- producing `CutHypEvOnSlot` from (2.77) is circular;
- producing `Lemma514` from the sharp hierarchy it is used to prove is circular;
- producing `Eq45FlowInputs` from (2.78) reverses its role in Step 4;
- producing the (5.48) package from (2.79) reverses its role in Step 5.

The fixed first-cell theorems certify compatibility of selected hypotheses and endpoints, but they do
not change any universal classification above.

record constructor, toy probe, or theorem restricted to the current fixed first cell does not discharge
