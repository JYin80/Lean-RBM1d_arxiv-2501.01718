# T626 — Dependency-boundary preflight for the T621/T616 floored-flow and `E \otimes E` route

## Verdict

The mathematical route identified by T621 and T616 is viable **as a conditional route**, but the current suggested Gaussian imports do not form a pre-Step-3 dependency boundary.  In particular:

* `RBM.LKDecayQuant.FlowInputs'` and its floored decay producer are theorem-level independent of Step 3, but their module is transitively polluted by `Hierarchy.Step45` through one generic high-probability lemma imported from `Hierarchy.Step1`.
* `RBM.Step2PP.flow_xiL_apriori_le'` is theorem-level independent of Step 3's sharp-loop conclusion (2.77), but its module is transitively polluted by `Hierarchy.Step45` through `ChargeReduce`/`StepGlue`.
* `Gauss.APrimeQVEndpoint`, `Gauss.XiLKTwoCutInitial`, and `Gauss.MomentDuhamelHypGauss` are not admissible imports for the proposed upstream `E \otimes E`/quadratic-variation route.  They carry Step 4–5, Step 6, first-cell, A-prime, or Theorem-2.21 assembly dependencies.
* `Gauss.MomentDuhamelRhs`, `Gauss.XiLow`, and `Hierarchy.EEBridge` are clean with respect to the forbidden families audited here.

Therefore no `hEE`, QV, six-step, `hfamily`, `APrimeSlot'`, or T230 implementation should be dispatched from this preflight.  The first safe implementation slice is the one-theorem import refactor in [First implementation slice](#first-implementation-slice).  It changes no signature and introduces no new mathematical hypothesis.

### (2.75) and (2.76): same window and same sample

Formula (2.75) is the uniform local law on the same interval:

```text
||G_u - m||_max \prec (W ell_u eta_u)^(-1/2),   s <= u <= t.
```

Formula (2.76) is stated immediately afterward for the same `u in [s,t]`, the same flow realization, and charge `sigma=(+,-)`.  Consequently the intended adapter must accept a simultaneous pair

```lean
hlocal : LocalLawFlow X E s t
hdecay : AprioriDecayFlow X E s t
```

for the **same** `X`, `E`, `s`, and `t`.  Separate existential witnesses cannot be combined.

There is also an exact-form issue that must not be hidden by the dependency refactor.  The PDF prints the tail in the form

```text
R_{s,u}^4 A_u^(-2) exp(-sqrt(dist/ell_u)) + W^(-D),
```

whereas the frozen Lean declaration `AprioriDecayFlow` in `Flow/Hypotheses.lean:364` uses

```text
R_{s,u}^4 A_u^(-2) * (exp(-sqrt(dist/ell_u)) + W^(-D)).
```

This report does not change that established public signature.  Consumers must distinguish the literal paper formula from the current Lean hypothesis instead of calling the latter verbatim without qualification.

### Floored Lemma-5.9 chain

The exact current chain is:

```text
LocalLawFlow + AprioriDecayFlow + a Gaussian LDE-with-floor producer
    -> FlowInputs'
    -> highProb_eeDecay_of_inputs'
    -> highProb event controlling eeField
    -> stochDom_norm_eeField.
```

`FlowInputs'` quantifies over every `tau>0` and `D'>0` and asks for `gdel`, `Phi`, and `eps` satisfying eventually

```text
gdel <= 1/2,
1 <= Phi,
36 * Phi * gdel^2 <= 1,
0 <= eps,
Phi * sqrt(2*eps) <= N^(-D').
```

The flexible exponent choice from T621 is arithmetically sound:

```text
gdel_N = N^(-alpha),   Phi_N = N^beta,
alpha>0, beta>0, beta<2*alpha,
eps_N = N^(-2*(D' + beta + 1)).
```

Here `eps` must be selected **after** the universally quantified `D'`.  This gives both `36 Phi gdel^2 <= 1` eventually and `Phi sqrt(2 eps) <= N^(-D')` eventually.  These numerical facts do not themselves supply a simultaneous stochastic witness.

### (5.42): four-coordinate transport factor

Formula (5.42) contains the expansion factor `(eta_u/eta_t)^4`; the following prose says that this expansion factor is absorbed later by changing an exponent.  With a moving endpoint `v`, this is

```text
R_{u,v}^4 = ((1-u)/(1-v))^4.
```

The power four is forced by the four coordinates of the doubled two-loop tensor.  The clean moment lemma `Gauss.momNorm_Uker_apply_le`, specialized to `n=4` and `C=R_{u,v}`, gives this factor directly.  It sums the kernel mass outside the moment norm and therefore introduces no inner `L_N^4` factor.

### U-kernel moment route

`APrimeQVEndpoint.norm_Uker_eeFun_le_ratio` proves the right pathwise ratio-four inequality, but importing its module brings the forbidden closure above.  The proof need not be reused as an import.  A clean future QV core can instead specialize `MomentDuhamelRhs.momNorm_Uker_apply_le` at four coordinates and use `SumZeroDyn.norm_xi2_le` to establish the coordinatewise kernel bound.  This yields

```text
R_{u,v}^4 * A_u^(-4) * eta_u^(-1) * flowR^5
```

pointwise in the outer time/charge/label index.  The required order of operations is:

1. use `momNormDom_of_stochDom` with the full time/charge/label index;
2. use Lyapunov (`2p -> p`) through `hEEmom_of_momNorm_two_mul` or `hEEmom_of_momNormDom`;
3. use `momNorm_Uker_apply_le` with kernel mass outside the norm;
4. only afterward form any outer all-charge family.

Taking an inner supremum over `LoopArg` before the moment estimate would create the forbidden cardinality loss.

The closed endpoint `v=s_N` is a zero-length interval case on the same sample.  It does not authorize an independent copy or a separately chosen witness.

## Clean adapter boundary and exponent budget

The eventual clean floored-flow adapter should take, rather than manufacture, the same-window inputs

```lean
hlocal : LocalLawFlow X E s t
hdecay : AprioriDecayFlow X E s t
hlde   : the two floored LDE stochastic dominations
```

together with explicit regime and endpoint-scale bounds.  It should not import `GoodSetFlow`, `LDENetClose`, `Cond272Reg`, `Thm221Bare`, or `Thm221NoEL` merely to recover those facts.

For a Gaussian specialization, `ldeFlowDom_floor` currently asks for `K>=0` and an eventual endpoint bound `N^(-K) <= etaT E (t N)`.  Converting (2.75) into the good event also needs an explicit polynomial endpoint scale gain, for example `N^c <= B.scale E N (t N)` eventually with `c>0`, plus scale monotonicity.  A safe concrete internal choice is `alpha=beta=c/4`; then `0<beta<2alpha`.  This is only a proposed arithmetic instantiation, not a witness theorem.

`Cond272` alone supplies no positive polynomial gain.  Importing `Cond272Reg` from `Thm221Bare` solely for convenience would enlarge the boundary unnecessarily; the future adapter should state the exact lower bounds it uses.

## Nondegenerate satisfiability audit

No existing clean theorem was found that simultaneously provides, for one Gaussian sample and one target interval,

```text
LocalLawFlow X E s t,
AprioriDecayFlow X E s t,
the endpoint polynomial scale bounds,
and the floored LDE input.
```

`XiLKTwoCutInitial.positive_grid_boundsCore_witness` is not such a witness.  It neither contains the same-parameter pair `(LocalLawFlow, AprioriDecayFlow)` nor avoids `Thm221NoEL`; its module closure includes actual (2.77) production.  Combining separately existentially chosen samples would be invalid.

Thus the assumptions are numerically consistent but not yet nondegenerately inhabited in the required simultaneous form.  The smallest missing mathematical implication is a compiled, same-sample, same-window producer for `(2.75),(2.76)` together with the endpoint polynomial bounds on the actual target grid.  Until that exists, only signature-preserving refactors are honestly dispatchable.
