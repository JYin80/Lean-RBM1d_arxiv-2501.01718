The moved definition now exposes directly

```text

  - B.Kval E N u (LoopData.idx (sigPM, a))
```

   ```text

   ```

   `SumZeroDyn.lkT` in that hypothesis and remove the now-inapplicable wrapper unfold from

   ```text
   unfold SumZeroDyn.lkT at hswap
   rw [lk, ← hswap, hidx]
   ```

### Frozen named-argument API

The first clean-core draft used ASCII binder names `eps` and `heps` in public declarations
whose pre-extraction spelling was `ε` and `hε`.  Lean proposition types do not record this as
a mathematical difference, but named arguments do form a source API.  The existing calls in
`APrimeSmoothWeightActual.lean` therefore failed at three sites with an invalid named
argument `ε`.  T659 must retain the original `ε`/`hε` spelling on every moved public
declaration and update only private/internal references as needed.  This is an API
restoration, not a new theorem or a changed hypothesis.

## 5. Mathematical boundary: what the bundle does not prove

The formula-level audit agrees with T650:

- Formula (2.73) is a same-sample, all-charge-word, closed-window estimate for
  `s <= u <= t`, with the conversion `xiL_6` controlled by `flowR^5`.
- The target QV statement quantifies
  `v ∈ netFinset s t (meshK 21 (1/2)) N` with `s N < v`, and then continuously over
  `s N <= u <= v`.  The variable `u` is not required to be a net point.
- The endpoint `v=s N` is handled only by the zero-length integral; it is not supplied by a
  positive-cell theorem.
- Formula (5.42) retains the four-kernel transport factor
  `R_(u,v)^4 A_u^-4 eta_u^-1 flowR^5`.  The time net contributes only the point `v` and its
  closed-endpoint membership.

Consequently this bundle is not `hfamily`, `APrimeSlot'`, the T230 A-prime theorem, QV
closure, a six-step closure, or paper closure.  It creates neither a same-sample QV producer
nor a finite-support/probability conclusion.
