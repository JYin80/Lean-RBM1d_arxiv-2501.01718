# T288 — top-length `Ξ^{(L−K)} ≺ 1` dependency audit

## Result

There is no noncircular producer among the current Step 1/2/3 declarations for
`StochDom B.P (Step3.flowXiLK X E s t m) 1` at every `1 ≤ m ≤ n+2` before the Lemma 5.14
family is established. In particular the base length `m=2` is circular. I therefore did
not create `Gauss/Lemma514XiTop.lean` or add a renamed assumption. T278 files and
`RBM1D.lean` were read only.

## Exact dependency cycle

`Gauss.psiF_stochDom_etaT_inv_of_drift_inputs` (`Lemma514QAssembly.lean:3045`) takes
`hxi : ∀ m ∈ Icc 1 (n+2), flowXiLK_m ≺ 1`. It uses `hxi 1` for the drift main bound and
`xiSum_stochDom_of_flowXiLK hxi` for the additive `W L δ · xiSum` error. At `n=0`, this
demands `flowXiLK_2 ≺ 1` while the intended output is `Lemma514 2`.

The apparent all-length supplier is `Step45.xiLK_le_one_of_hyp`
(`Hierarchy/Step45.lean:242`). Its signature explicitly takes
`h514 : Step3.Lemma514 … 2`. Its proof obtains `(5.125)` at length `2` through
`eq5125_of_lemma514 h514` (`:163`), and then `xiLK_le_one` (`:183`) uses that `(5.125)`
in the `n=2` induction branch. The model wrapper
`Gauss.xiLK_le_one_of_steps34` (`Gauss/Step6EnvWindow.lean:2434`) passes the same `h514`
unchanged. `Step45.flow_sharpLmK` (`Hierarchy/Step45.lean:312`) applies
`h514 2 le_rfl`. The `Step2PP` bootstrap is not an independent source:
`xiLK_two_improve_of'` (`Hierarchy/Step2PP.lean:210`) also takes `Lemma514 2`, as does
`flow_hs2_of'` at its call site `:728`.

Thus the proposed closure would be

```
Lemma514 2
  → Step45.xiLK_le_one_of_hyp
  → flowXiLK_2 ≺ 1
  → T278 psiF_stochDom_etaT_inv_of_drift_inputs (n=0)
  → Lemma514 2.
```

`Gauss.highProb_flowXiLK_le` (`Step6EnvWindow.lean:1947`) only converts an existing
`flowXiLK_m ≺ 1` into a high-probability event, so it does not break the cycle.
`Step3.xiLK_le` (`Hierarchy/Step3.lean:643`) gives the weaker control
`(A_s)^{1/2}`, and its `Step3.Hyp` has a `lemma514` field at every length `≥3`
(`:416–427`); it is not an all-length pre-Lemma-5.14 supplier either.

The four fields of `Gauss.Lemma514Premises` (`Lemma514Moment.lean:388`) at target length
`2` control `XiL_6`, `XiLK_1`, `XiLK_2²/A`, and `XiL_3`, respectively. They do not control
`XiLK_2` by itself. This is a genuine logical gap in those four fields: in an abstract
one-point probability model, set `A_N=(N+1)²`, `X_1=0`, `X_2=N+1`, all relevant `Y=0`,
and `Λ=Φ=1`. The quadratic premise is exactly `X_2²/A_N=1`, but `X_2` is not `≺1`
(take exponent `τ=1/2`). This witness concerns the abstract premise interface; it does
not assert that the concrete Green-function model realizes these values.

## Smallest honest alternative for T278

The **additive** drift error does not need `XiLK_{n+2}≺1`. It only needs a polynomial
bound, because its coefficient is `δ=N^{−D}` with `D` chosen after `n`. Such a bound is
available without Lemma 5.14: `Gauss.norm_gloop_le_det`
(`Gauss/Envelope.lean:415`) gives, at length `m≥1`,
`‖L_m‖≤η_u^{−m}W^{−(m−1)}` on every Hermitian sample. `Gauss.exists_norm_Kval_le_upto`
(`Gauss/Lemma514Holder.lean:835`) gives `‖K_m‖≤C_m A_u^{−(m−1)}` for
`2≤m≤n+2`; `Band.norm_Kval_le (n:=1)` covers length one. On the eventual window,
`SumZeroDyn.flow_crude` gives `A_u≤N`, `(1-u)^{-1}≤N`, and `W≥1`;
since `η_u^{-1}=(Im m_E)^{-1}(1-u)^{-1}`, for each fixed `m` the resulting
`XiLK_m= A_u^m max‖L_m-K_m‖` is bounded by
`(Im m_E)^{-m}N^{2m}+C_m N` for all samples. Consequently `xiSum_{n+2}` has a
deterministic polynomial bound. A primed T278 envelope could replace only its
`hxiS`/`xiSum_stochDom_of_flowXiLK` branch with this bound and increase the decay
exponent `D₁`; it should retain the separately needed `XiLK_1≺1` and `xiRhs≺1`.
The high-probability `FastDecay(H.F)` input is a separate T289 task.
