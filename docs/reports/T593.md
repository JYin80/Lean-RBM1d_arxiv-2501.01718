# T593 — preflight for the first general-moving drift time-integral budget

## Scope and verdict

This is a read-only mathematical and Lean-interface audit.  The audited local source is
`paper/250520-YinJun-v2.pdf`, especially (5.34), (5.35), and (5.41).  The audited Lean surface is
the raw declaration surface of T579, T584, and T586 together with
`APrimeDriftTimeFamily`, `APrimeDriftEnvelope`, `APrimeDriftIntegralBudget`, and the first-cell
drift files only as boundary-pattern references.

**Verdict: no honest general-moving drift time-integral budget is currently dispatch-ready.**
The smallest blocker is the missing favorable-event implication from T586's bound on the
linear source `EGDef.eGpm` to a pointwise bound on the actual normalized propagated drift
`APrimeDriftTimeFamily.driftAt`.  Time integration cannot start before this implication is
proved.  The obstruction is substantive: `driftAt` contains the full `DriftDef.driftF`, hence
also the quadratic gluing term (5.34), then applies `Uker`, and finally divides by the exact
endpoint normalization `driftScale`.

There is also a literal type mismatch that must be visible in the dispatch: T579, T584, and
T586 each declare

```lean
private noncomputable abbrev d : Dims := Dims.exampleGrow
```

so the current common event and source estimates do **not** quantify an arbitrary
`(d : Dims)`.  The smallest blocker below can therefore be stated honestly only for
`Dims.exampleGrow`.  A theorem with a leading arbitrary `(d : Dims)` would first require a
parameterized upstream T579/T586 event-and-source surface; inserting a dummy `d` that is not
the dimension used by the event is not a valid repair.

## What the paper requires

The paper separates two pieces of the raw drift:

1. (5.34) bounds the quadratic gluing source by
   `e (J*_{u,D})^2 [36 eta_u^-1 A_u^-1 + W L W^-D] T_{u,D}`;
2. (5.35) bounds the linear Green source `E^(G~)_u`, with a near contribution and a far
   `eta_u^-1 A_u^(-1/3) (J*_{u,D})^3` contribution;
3. (5.41) transports the linear source from `u` to the endpoint, with the explicit factor
   `(eta_u / eta_t)^2`.

Thus (5.41) is not, by itself, a bound for the complete drift.  It must be combined with the
quadratic row (5.34).  The later stopping statement (5.43) cannot be used as an input to this
bridge.

The current T586 bounds are deliberately less absorbed than the displayed paper row.  On the
same T579 resident and positive widened support, they retain exactly:

```text
Jbar_u = 1 + N^tauG *
  (9 exp(sqrt 3) * ((4 exp(1) + 2) N^(2 delta) ratR_u^4) + 2),

M_far(u) = eta_u^-1 * (4 N^zetaCtr ratR_u) *
  [cFar(W,ell_u) Jbar_u (flowDelta + W^-1)
   + Jbar_u sqrt(Jbar_u)
       (168 A_u^-1 + L sqrt(W^-D) / ell_u)],
```

and the far conclusion is `|eGpm_b| <= M_far(u) T_{u,D}(dist_b)`.  The near conclusion is

```text
|eGpm_b| <=
  4 N^(zetaCtr+zetaSrc) eta_u^-1 ratR_u^3 cNear(W,ell_u)
    T_{u,D}(dist_b)
  + (4 N^zetaCtr ratR_u) (ell_u eta_u)^-1 L
      (eta_u^-1 Jbar_u T_{u,D}(gap(W,ell_u))).
```

No `ratR <= 2`, no endpoint substitution, and no stopping absorption is available or should
be introduced in the first bridge.

## Exact Lean interface audit

### T586 supplies a source, not the drift integrand

`APrimeGeneralMovingDriftSource.eventually_far_on_common_support` and
`eventually_near_on_common_support` have the correct order

```text
E,D,c; s,t; deterministic window hypotheses;
zetaSrc,zetaCtr,tauG,delta independently;
p with 1 <= p;
eventual N; positive k; one common-event omega; positive widenedW;
u in the closed active cell; output pair.
```

They bound `EGDef.eGpm` only.  In contrast,
`APrimeDriftTimeFamily.driftAt` is definitionally

```text
|| Uker(u,v) (DriftDef.driftF at u) a || /
  [T_{v,D}(dist_a) * (eta_s / eta_v)^4].
```

For the `(+,-)` two-loop coordinate, the exact identity
`DriftDef.driftF_zero_eq_eGpm_add_quadGlue` and
`Step2FarInputs.quadGlue_pm_eq_eLL` show that the missing summand is precisely the quadratic
source controlled by `Step2.norm_eLL_le`:

```text
M_quad(u,omega) = exp(1) * jS(u,omega)^2 *
  [36 eta_u^-1 A_u^-1 + W L W^-D].
```

Here `jS = Step2.jS` is the actual `J*` of (5.34).  T586's `Jbar` bounds the block functional
`APrimeJG.jG`, not `Step2.jS`; there is no declaration permitting `jS <= Jbar`.

### Propagation and normalization

`Step2.norm_Uker_flow` is already available and has the exact deterministic form

```text
|source_b| <= M_u T_{u,D}(dist_b)
  ==> ||Uker(u,v) source||_a
      <= M_u (eta_u/eta_v)^2 xiK T_{v,D}(dist_a).
```

Dividing by the literal `driftScale` cancels `T_{v,D}` and gives

```text
M_u * xiK * (eta_u/eta_v)^2 / (eta_s/eta_v)^4
  = M_u * xiK * ratR_u^-2 * ratR_v^-2.
```

The last equality uses positivity and
`ratR_x = eta_s/eta_x`.  In particular, the Lean normalization contains the fourth endpoint
power and must not be replaced by only the paper's transport factor `(eta_u/eta_v)^2`.

The near residual is not yet in the `M_u T_{u,D}` form required by
`norm_Uker_flow`.  The existing `APrimeDriftNearAbsorb.residual_ratio_le` is the honest bridge:
with `C=2`, `zeta=zetaCtr`, `r=ratR_u`, and `J=Jbar_u`, it converts the residual to a near
tail coefficient while retaining

```text
4 N^zetaCtr * [L Jbar_u / (ell_u eta_u ratR_u^2)] *
  A_u^2 * exp((log W)^(3/4)) * T_{u,D}(gap(W,ell_u)).
```

This coefficient, multiplied by `eta_u^-1 ratR_u^3`, must be retained until a later
deterministic absorption theorem proves a smaller row.

## The single smallest dispatch item

The next ticket should prove one pointwise theorem, for the current fixed
`d = Dims.exampleGrow`, with the same quantified prefix and support as T586:

> On every positive active cell, for the same T579 `commonEvent` resident and the same positive
> target-mesh `widenedW`, every `u in [s_N,v_k]` and every two-loop label `a` satisfy
>
> ```text
> driftAt d E D N sigPM a (s N) v_k u omega
>   <= xiK * ratR_u^-2 * ratR_v^-2 *
>        (max(M_near(u), M_far(u)) + M_quad(u,omega)),
> ```
>
> where `M_far` is exactly T586's far coefficient above, `M_near` is T586's principal near
> coefficient plus the literal `residual_ratio_le` coefficient above, and `M_quad` is exactly
> the (5.34) coefficient with the actual `Step2.jS`.

This is the smallest missing implication because it uses only existing upstream facts:

- T586 near/far `eGpm` estimates on the one T579 event;
- `driftF_zero_eq_eGpm_add_quadGlue` and `quadGlue_pm_eq_eLL`;
- `Step2.norm_eLL_le`;
- `APrimeDriftNearAbsorb.residual_ratio_le`;
- `Step2.norm_Uker_flow`;
- positivity of `driftScale` and the exact definition of `driftAt`.

It must not assume a pointwise `driftAt` bound, `hfamily`, `APrimeSlot'`, stopping, BDG, any
six-step conclusion, or an already integrated drift budget.  A minimal import probe containing
only `APrimeGeneralMovingDriftSource` and `APrimeDriftTimeFamily` successfully resolves the
drift decomposition, (5.34), propagation, and time-integrability declarations, so this bridge
is acyclic.  T584 is not an input; it is only the model for preserving the common
event/parameter/endpoint surface.

## Why the integral theorem must wait

### The finite-time integrability producer is already adequate

`APrimeDriftTimeFamily.intervalIntegrable_momNormW_driftAt` is genuinely general in
`(d : Dims)`, `E,D,N`, the charge pattern and `a`.  For any fixed measurable weight
`0 <= w <= 1`, it proves interval integrability on the closed interval `[s,v]`, including both
endpoints.  The exact target `widenedW` is nonnegative and at most one; its measurability is
obtained by unfolding `widenedW` and using `measurable_prefixSoftW` with measurability of the
actual deterministic field `APrimeGeneralMovingDetFields.J`.  Therefore no artificial
open-interval truncation at `u=s_N` or `u=v_k` is needed.

This theorem proves finiteness only.  It does not supply a numerical upper bound for the
integral.

### The deterministic integral envelope is not yet connected to the actual drift

`APrimeDriftIntegralBudget.driftEnvelope` is the four-row deterministic function

```text
ratR_v^-2 * [
  powerRate(-1/2)
  + N^(4 delta) A_v^-1 powerRate(6)
  + N^(2 delta + tau) A_v^(-1/2) powerRate(11/4)
  + N^(3 delta + 3 tau/2) A_v^-1 powerRate(9/2)].
```

`eventually_integral_driftEnvelope_le` integrates this function.  It does not mention
`driftAt`, T579's event, T586's source, or the target weight.  Correspondingly,
`direct_integral_drift_budget` explicitly assumes the missing pointwise premise
`Adr(u) <= driftEnvelope(u)`; it does not prove that premise for the Gaussian model.

No audited declaration proves that T586's exact `N`, `W`, `ratR`, `Jbar`, near-residual, and
quadratic `jS` rows are dominated by this four-row envelope.  Claiming the integrated envelope
as an actual Gaussian drift budget now would therefore assume the main estimate.

`APrimeDriftEnvelope` does not fill this gap.  Its `QbActual` construction is a finite-size
maximum for the fixed first-cell prefix and proves no general-moving, eventual-in-`N`
domination of the T586 profile.  Likewise, T584's extra exponent-room hypothesis belongs to
its QV absorption route; the pointwise drift bridge should preserve T584's shared
`zetaSrc,zetaCtr,tauG,delta,p`, event, weight, and endpoint order, but should not import the QV
profile or add `hroom` unless a later drift-specific absorption calculation actually consumes
it.

### Favorable/complement split is a later obligation

After the pointwise blocker is removed, a weighted `momNormW` estimate still needs the standard
two-part argument:

1. on `commonEvent`, use the pointwise profile wherever the target widened weight is positive;
2. on its complement, pay the event probability against an all-sample polynomial envelope for
   the same general-moving `driftAt`.

The first-cell `weighted_norm_le_of_weighted_event` pattern is generic and reusable, but the
audited repository surface contains an explicit all-sample polynomial drift envelope only for
the fixed first-cell regime `E=0`, `D=60`, `s=0`, `v<=1/2`.  The general
`Gauss.exists_driftF_envelope` gives a finite deterministic window bound, sufficient for
continuity/integrability, but not the explicit eventual `N` power needed to pay a high-probability
complement.  This is downstream of the single pointwise blocker above and is not a second
dispatch recommendation in this report.

## Endpoints, `k=0`, and non-vacuity

- **Positive cells:** the T586/T584 support is exactly `1 <= k <= cutNetTop`, with
  `v_k = cutNetPt ... k` and `u in Set.Icc (s N) v_k`.  Both endpoints must remain in the
  pointwise bridge and in the later integral.
- **`k=0`:** `cutNetPt ... 0 = s N`, so the interval is `[s_N,s_N]`.  Its drift integral is
  zero by `intervalIntegral.integral_same`.  One must not infer that
  `driftAt ... (s N) (s N) (s N)` is zero; for a general moving window it need not be.
- **`u=0`:** this occurs only when `s N=0`.  The finite-time integrability theorem includes it,
  and the source/transport statements have no singular exclusion there.  The later proof must
  not replace the closed interval by `(0,v]`.
- **Positive-window witness:** T579/T586 provide an eventual first-cell realization with
  `s_N=0<t_N`, an actual resident of the same `commonEvent`, `k=1`, and target
  `widenedW=1` for every `p`.  Thus the current fixed-`exampleGrow` pointwise blocker is
  non-vacuous.  It is not a witness for an arbitrary `d : Dims` theorem.
