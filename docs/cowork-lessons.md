## 1. 分工与节奏

* **两层结构**：Cowork 只做调度（读论文、定路线、写工单规格、审计、蓝图、论文改动预算），**不写 Lean**；终端里的 Claude Code 负责写 Lean、`lake build`、提交，并扇出子 agent 并行。Jun 只在两处出场：数学/论文陈述的裁定、范围变更。
* **心跳**：`send_later` 每约 12 分钟一次，**任何情况下不超过 20 分钟**（Jun 的规则；我曾因终端空闲自行放慢到 30 分钟，被纠正）。每次心跳的固定动作：
  1. `git log` / `git status` / `build.log` 的 mtime 与结尾（全量构建是否绿）；
  2. 读每张新完成单的提交信息 + STATUS 段落，按 §3 的清单审计；
  3. 队列深度：待认领 ≥ 3；不足就从审计出的余项开单；
  4. paper-deltas 编号查重、分配数字号；
  5. `content.tex` 变了就刷新蓝图 artifact；
  6. 结束前排下一次心跳。
  **先排下一次心跳，再做本次的活**：上下文压缩或长审计会把「结束前排心跳」挤掉（本项目发生过一次）。
* **报告给 Jun 的节奏**：每次心跳一小段话；只有「需要他定」的事才提问，且一次一件、给出倾向。无人值守时路由类决定自己做，论文陈述类记下等他。
* **并行车道按文件划分**：两张单改同一文件就串行；给 Jun 报「最多几条车道」时附上车道↔文件表。
* **agent 集体中断（HTTP 529 / 会话退出）后的处置**（2026-09-22 01:17）：十一个 agent 同时死掉。协调者做对的事：逐单登记半成品（文件、是否编译、「未验证、不要当成已完成继承」），把表恢复成真实状态，再按并发上限重派。重派的 agent 发现「登记为空的」其实有 1024 行已编译、「登记为红的」其实已修好——**半成品登记是快照，重派时必须重新核，不能照登记处置**。
* **会话重连会重置删除权限**：Cowork 这边重连后 git 删不掉自己的 `.git/HEAD.lock`，锁文件残留会卡住终端的下一次 commit。先把锁 `mv` 进 `.git/_to_delete/` 应急，再用 `get_device_info` 取**规范绝对路径**申请一次删除权限。每次重连后第一次 commit 之后都要 `ls .git/*.lock` 核一下。
* **并发上限**：终端侧把并发 agent 上限定在 6；超过后更容易撞 529。
* **推送**：Cowork 所在的执行环境对 GitHub 没有凭据，`git push` 失败是常态；Cowork 只在本地提交文档，推送由终端协调者做。

## 2. 写工单规格的要点

* **每张单写清**：来源（哪张单的余项、哪条审计）、论文位置（**公式/定理编号为主**，页码为辅，未编号的显示式写「(5.67) 之后那行」并引一句原文）、要交付的**具体声明名**、**验收标准**（通常是「某个探针的假设表里不再有 X」+ 公理干净 + 可满足性见证）、禁止事项（不改冻结签名、不许为变绿放宽判据、不许按定义造数据字段）。
* **第 0 步（只读）先行**：对风险大的单，先让 agent 交一份只读分析（指数表、归因、二选一的判断），Cowork 审完再实现。T174（指数表重算）、T195（行和 R 依赖）、T164（`MinorGood'` 可满足性）都是这样发现根本问题的。
* **「若按字面为假，停下报告，不要硬凑」**写进每张有风险的单。
* **转派前重读原单全文**：我把 T191 的四项余项只转了一项（`bddT`），agent 按规格做完才发现漏了——规格漏项比代码 bug 更贵。
* **余项必须点名到字段名与定义位置**，否则会出现「归包络那条线」这种没有收件人的转述（滞留审计 B.1）。
* 规格里给出的「建议做法」要标明是猜测；agent 推翻时接受（T171 推翻了我给的 `hslice` 形状，因为它本身又是不可满足的）。
* **「无主」项当次心跳全部开单**：完成报告里凡写「无主」「没有单负责」「建议新单」「同线续做」的，Cowork 在同一次心跳里一条一单开出去（17:15 一次开了八张 T209–T216）。拖一次心跳，它们就会被后续单的「更正」淹没。「同线续做」尤其危险——没有状态栏、没人认领，要么单独开单并注明「原 agent 仍在做就由它认领」，要么在原单状态栏写明续做中。
* **卸假设的单要禁止「换名留字段」**：验收写成「假设表里没有 X，或 X 只经某个已存在的上游接口出现」，并明文禁止把 X 改名成新字段留下（T216 的 `M_m`）。
* **「原地替换」类规格要先核前提**（T201）：我写「把裸行和逐处换成 `Q_u` 投影后的 (7.16) 档」，但 (7.16) 要求 sum-zero，而原地的三个张量都不是——投影后的版本是**另一条陈述**（另一个接口字段）。写「把 A 换成 B」之前，先确认 B 的前提在 A 的位置上成立；否则规格应写成「改走接口 B′」。
* **agent 标「范围问题」的，Cowork 先判是不是路由**（D14）：只要改动是**论文自己的证明路线**、论文陈述一字不动，就是路由类，Cowork 当次裁定并开单；只有改论文陈述或增删定理才上交 Jun。
* **agent 交「待 Jun 定夺」的多选项时，先对照 Jun 已有的裁定**（D15）：选项 1/2 要给模型加滤子，与 Jun 早先选的「只在一时刻律层面对齐」(a) 直接冲突；剩下的选项不碰范围、不改论文陈述，就由 Cowork 当次定，并在给 Jun 的汇报里写明「已代定、可推翻」。
* **同一数学对象出现在两条线时**（T201 与 T214 的 `Q_u`），规格里写「定义只许一个，开工前先读另一条线的文件」，并建议由先做的 agent 续做。

## 3. 审计清单（每张完成的单都过一遍）

编译通过 + 公理干净 **不等于有内容**。本项目一天之内踩了七次「空真」和数次「fiat」：

1. **fiat（可被平凡满足）**：结构里有自由数据字段，定理对它全称量化 → 取一个平凡值就满足。例：`SumZeroDyn.Hierarchy` 的 `mart := 残差`；`MomentDuhamel.Hyp` 早期的 `EE` 字段；Step 6 的 `DLK/DG`（取 0 即满足 `hG`）；T198 的 `FarInputs`（见证取漂移 = 0）。**修法**：数据改成定义（`def`），或由恒等式钉死（`F_unique`），交付时写 `example` 证明实例里没有可自由赋值的数据。
2. **空真（不可满足）**：
   * 对所有样本点 `ω` 量化的确定性不等式——`ω = 0`（`H = 0`）或单坐标很大就破（`MinorGood`，T164/T172）；
   * 对所有矩阵量化，而对象只在 Hermitian 集合上合格（T145、T180、T187）；
   * 正则性要求高于证明所需（时间方向 `C²` 其实只要 `C¹`，T191）；
   * 量词次序：论文是「`p` 固定、`N → ∞`」，写成 `∀ p N` 就空（T188）；
   * 端点：`√u` 在 0 不可导，闭区间上要导数在 `s = 0` 时不可满足（T152）；
   * 常数不随参数增长的假设在实际窗口上不成立（T192/T195：行和常数要短窗口，而论文网格上窗口比恰为 `W^{τ′} − 1`）；
   * **时间参数的量化范围写宽了**（T205，第九例）：包络假设写成 `∀ v : ℝ`，证明里只在 `TimeIcc s t` 上用；`v` 越出窗口处被积量无界。判别法很便宜——把每条假设的量化范围与它在证明里被使用的范围对一遍；仓库里往往已有窗口版，形状对不上就是信号；
   * 接口本身在所需强度下不可满足（`FlucBound` 的 `B ≥ 64/65`，T172；`MinorDiffGainUpTo` 缺基数预算，T171）。
   **修法**：交付含新假设的定理时**附一个可满足性见证**（一组显式参数使全部假设同时成立），并且用**非退化**、最好是**临界尺度**的实例（T197 在 `J ≡ Θ` 处给见证）。
3. **死胡同 vs 污染链**：查到不可满足的假设后，先查下游有没有 `apply`——没有就是死胡同（加 `@[deprecated]` 护栏，T184），有就是污染链（必须修）。
4. **地基的可满足性**：最底层的参数结构有没有居民（`Gauss.Dims` 一直没人给实例，T202）——这是可满足性审计的第 0 条。
5. **只动假设、不改结论**：放宽类的单（`0 < s → 0 ≤ s`）逐行看 diff，确认只有假设变弱；下游陈述用 `have : h1 = h2 := rfl` 编译验证逐字不变（T107/T183 的做法）。
6. **「已完成」的旧记录会过时**：清单类文档（T147）几小时后就会被新单改写；审计以编译探针为准，不以旧笔记为准（T176、滞留审计都发现了过时条目）。
8′. **单文件编译不算数**（T222）：`lake env lean <文件>` 不施加 library 的 `leanOptions`（`autoImplicit`），未定义标识符会被 auto-bound 蒙过；新文件收工前必须 `lake build <模块>`。
7. **找「谁产出这个假设」的元程序对 `def` 形状有假阴性**（T200）：按结论头常量搜生产者时，五条 `*Flow` 被误报为无生产者，实际是定义展开。`def` 形状的假设一律用裸 `:=` 探针逐条核。
8. **接口强弱链要编译出来**：`Thm221 → Thm221Reg → Thm221'`、`Cond272' → Cond272Reg → Cond272` 这类链写成定理；「A 形产不出、只产得出 A′ 形」（T204）这种缺口只有在链上逐个喂探针才看得见。

## 4. 论文保真

* **外部输入**：只允许用被引论文的**主定理**，逐字写成假设、量化在所有满足其前提的模型上；不得编造「类似结论」。**逐字核对原文**——本项目发现 [51] Theorem 2.2 字面只陈述 GOE，而论文用的是复 Hermitian；核对了替代文献 [35] Prop 3.3 后排除（它是关于显式密度的辅助命题、要全能量域局部律、还需再引一条外部结果）。结论写进最终报告与论文改动。
* **论文改动预算**：凡 Lean 发现论文要改的，分成「零陈述改动的澄清」（补一句、补一个因子、改下标）与「陈述改动」（必须 Jun 确认）；每条写明编号位置、改法、规模。本项目最终约 9 处，全部零重新编号。
* **我自己也会说错**：D12 时我说「Theorems 2.2–2.5 都不用 (2.71)」，Jun 据此选了 (a)；随后查原文发现 (2.71) 经 (2.62) 给出 Theorem 2.4 的 (2.8)(2.9)、Theorem 2.5 又用它们。**立即更正、给出不丢定理的新方案、请他再确认**。教训：给 Jun 的「某某不需要」类断言，先 grep 论文全文的引用链再说。
* **定义层面的「漏共轭」类错误，估计看不出来、等式看得出来**（T213）：`xi2` 第二半漏了 `σ̄`，因为 `‖ξ_i‖ = 1`，所有经它的**估计**都不受影响，但它被断言的**等式**为假。凡是只在范数里出现过的对象，要至少做一次**数值等式**自洽检查（T213 在 `L = 3` 上两侧独立求值），并做判别性检查（错误版本给出不同的数）。
* **逐字核对论文用页面图像，不用 pdftotext**：数学排版经 pdftotext 会丢上下标与符号。终端侧常没有 poppler，Cowork 把相关页渲染成图像逐式读（本项目以此查出 (5.99) 第一行反号）。agent 报「未能逐字核对」时，Cowork 当次心跳补做。
* **页码**：以编号为准；声明所用的版本（仓库 PDF 是基准版本）。
* **数学判断先让 Jun 回忆原意**：如 J* 的超线性（Jun：「当时是不想 keep checking (η_s/η_t) factor」）——作者的一句话能省掉一天的探索。

## 5. 文档与编号纪律

* **paper-deltas 编号**：并行 agent 各取 max+1 必撞（一天撞五次）。最终办法：agent 写临时号 `T<工单号><字母>`，数字号由 Cowork 在心跳时统一分配；已提交的号不改（改号由 Cowork 做并注明原号）。
* **决策项（D 编号）同理会撞**：D12 撞过一次；Cowork 统一编号。
* **只提交指定文档文件**；`docs/` 有他人未提交改动时，不提交那些文件，推迟到下次心跳。TASKS.md 一干净就立刻开单并提交，窗口很短。
* **「待 Jun 定夺」节**：终端 agent 不直接问 Jun，写进 STATUS 的专节，由 Cowork 分流——路由类（新文件还是就地改、哪张单负责）自己定并写处理结果；论文陈述类转给 Jun，附倾向。

## 6. 数学/形式化上的可复用做法

* **随机分析缺位时用「一时刻律」路线**：`H_u = √u·X` 与布朗模型每个时刻同分布；生成元恒等式 + 对矩的不等式替代 Itô/BDG；时间网替代不可数并；收口用「积分 + 取上确界 + 解二次不等式」而非常系数 Grönwall。
* **停时 → 光滑截断**：`χ(J*/Θ)` 在支撑上把超线性项线性化；去截断在概率层面、在前缀事件上无余项（T197）。截断函数要**具体构造**（T175 用五次 Hermite），不能只把它的性质当假设。
* **(η_s/η_t) 前因子**：论文说「无前因子」的地方，通常是先经求和为零算子 `Q_u` 投影再用更强的核估计；Lean 若走了更弱的核界（Lemma 7.1），就会在一般窗口上变成空真（T195）。
* **分层引用的三档核估计**（(7.1)/(7.14)/(7.16)）：先查清每一步该用哪一档。
* **过度量化的修法**：带撇版把 `∀ M` 放到 `∀ M Hermitian`，旧版保留并证明旧类嵌入新类；常能通过「投影后是旧类的真实例」免掉重证（T187）。
* **矩路线里「先相加再取模」**（T206）：生成元项 `Re(F̄𝓛F)` 与时间导数项 `Re(F̄∂_uF)` 必须合在一起再放缩——`∂_uΨ₁` 里的 `Θ` 与漂移恒等式里的 `genS` 正是在相加时相消；分开放缩会留下不小的 `U∘Θ(L−K)`。凡「两项各自有界、和却更小」的地方，检查引理是否过早取了模。
* **「一致于时间」的版本会让尖锐指示函数出事**（T216/D15）：论文在窗口 `[s,t]` 内用**终点** `t` 的阈值 `6ℓ*_t`，逐时刻陈述没问题；Lean 要 `∀ u` 一致的流版本、阈值随 `u` 走，泛函就会在阈值越过实现距离时跳，网论证与连续性自举都失效。修法：光滑截断 + 放宽阈值（只削弱过渡带），或窗口内固定终点阈值。
* **幂次「丢了」时先查归一化**（T207）：Lean 的 (5.47) 只到 `(η_s/η_u)⁴`，原因不是证明丢了两次幂，而是 bootstrap 的归一化从来没把它取出来。

## 7. 与 Claude Code 侧手册的对接（2026-09-21 16:30 起）

终端侧写了 `docs/agent-playbook.md`（「并行 agent 协调手册」，11 节），**写 skill 时两份合并**：本文是调度/审计/论文保真视角，它是派单 prompt 与集成视角。它补充了本文没有的几条，已吸收：

* **派单 prompt 的固定骨架**（8 项：硬规则、要什么与已有什么、可能过时的部分、可写/只读文件清单、纪律、以探针为验收、编译/提交协议、报告要求）。
* **只读审计编译的定理不入库**——报告里要标「编译过但未入库」，否则后来者以为有、grep 却为零（T195 的 7 条）。
* **按概念 grep，不只按名字**——互不 import 的文件会各造一份同义引理（`inv_sq_le_tailT` 两份等）。
* **单文件编译查不出跨文件重名**，跨切面重构必须交全量绿构建。
* **改共享文档的脚本**：终端侧曾把 `docs/TASKS.md` 从 2695 行截成 4 行（`s[:匹配点] + 新行`）。**永远 splitlines + 插入 + join，改完先断言行数不缩水再 add**。Cowork 自己的文档脚本也照此（本项目 Cowork 一直用唯一锚点 + `assert s.count(a)==1`）。
* **检查器要有总数守恒断言**：终端侧的蓝图预览脚本曾因标题含 `]` 静默丢节点、三次才发现。Cowork 的蓝图生成器（`bp/paper.py`、`build.py`）已于 16:30 加上「环境数 ≠ 解析节点数就退出」的守卫。
* **带证明的否定结论是最有价值的产出**（`LDENetClose` 不可证、`MomentHyp.step` 冻结形不可证、裸 `Cond272` 不够、T198 形的 `cFarStep ≺ 1` 为假……），prompt 里要明说「精确报告短在哪个因子，能编译成定理最好」。
* **每次集成都问：这次结论是否推翻了先前转述给 Jun 的东西？**——今天推翻了五次，每次都要当面更正。
* **「做完就能交 X」的工单预言要当假设看**（T206）：规格说「余三步」，做完才发现还差两项没点名的。开单时写「据目前所知还差 …；做完后重跑 X 的探针，列出实际余项」。
