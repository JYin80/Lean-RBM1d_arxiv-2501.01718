# T441 — actual weighted-generator and `hG` interface audit

## Verdict

The actual Gaussian generator side is mathematically sound.  At the moving
first-cell endpoint, the current declarations already identify the exact
drift, the exact uncut quadratic variation, the canonical smooth weight and
its derivative, and the positive-time weighted derivative identity.  No
additional model premise is needed for the pointwise generator inequality.

The concrete `hG` is nevertheless **not yet a current Lean consequence**.
There are two distinct remaining gaps.

1. The sharp favorable-event estimates have not yet been exported in the
   exact actual weighted-rate forms.  T431 and T433 still need to be composed
   into the absorbed `driftAt` rate; the live T438 file has no final current
   `qvAt` theorem; and T439's stored-time raw QV still has to be absorbed and
   passed through T333's prefix-gradient contraction.
2. T440 proves time integrability for the chosen near-only
   `crossAt 0 0 v κ`.  The actual cross consumer T361 instead produces a
   full joint prefix-gradient/current-QV rate.  There is no theorem fitting
   that full rate pointwise into `crossAt`, including both far QV rows and
   the complement error.  Thus T440's three clauses cannot simply be paired
   with the existing T361 bound.  One must either prove this exact fit or use
   the full T405 cross profile as `B` and prove its time integrability.

The inference that the weight derivative vanishes outside an unrelated
`Good` event is false and is not needed.  The sound route is the transition
indicator followed by a `Good`/`Goodᶜ` split of the entire joint product,
with a global polynomial envelope on the complement.

Multiplication by
`APrimeSmoothWeightActual.weight_nonneg` gives `momFlowDeriv_le.hle` for

## 4. Exact cross-term route

T361 defines

```text
T_k = {1 < prefixSample/threshold < 2},
B_k(omega) = sqrt(quadVar(prefixMatrix)(Xmat omega))/threshold,
Z_r(omega) = 1_{T_k}(omega) B_k(omega) sqrt(Q_r(omega)).
```

`APrimeCrossJointSplit.crossAbsSum_active_le` is a global pointwise theorem.
The cutoff-chain derivative is bounded by the indicator of `T_k`, so the
cross absolute sum vanishes off the actual transition region.  It retains
the common Gaussian coordinate, the weight gradient at `Xmat omega`, and
the moment gradient at `Hflow_r omega`; it does not identify these two
matrix arguments.

For `r>0`, `crossPart_active_le_jointEvent` gives

```text
crossPart(r)
 <= (1/(2 sqrt r)) * Cs(Pmom) * phi(r)^((2Pmom-1)/(2Pmom))
      * (b sqrt(q) + Eall rho^(1/(2Pmom))),

Cs(Pmom) = (2 Pmom)^2 * 15/8.
```

Its favorable hypotheses are only

```text
B_k <= b,  Q_r <= q  on Good intersect T_k.
```

Its complement hypotheses are

```text
B_k sqrt(Q_r) <= Eall  on the whole sample space,
P(Good^c) <= rho.
```

Therefore the exact `momFlowDeriv_le.hcross` follows with

```text
Bfull(r) = Cs(Pmom)/(4 Pmom sqrt r)
  * (b(r) sqrt(q(r)) + Eall(r) rho^(1/(2Pmom))).
```

This is the correct event split.  `Good` is never differentiated.  There is
no premise and no valid deduction that `wD=0` on `Goodᶜ`.

For the drift and QV norms the analogous support-local route is also sound.
Write `w=c_k^(2Pmom)`.  Then

```text
momNormW P w Pmom G_r = ||c_k G_r||_(2Pmom),
rateNormW P w Pmom Q_r = ||c_k^2 Q_r||_Pmom.
```

Apply `APrimeBadSplit.weighted_norm_le_of_event` with unit weight to
`c_k G_r` and `c_k^2 Q_r`.  On `Good` but outside the positive cutoff
support these observables are zero; on `Good` inside the support the sharp
profiles apply.  This avoids strengthening a support-local estimate to all
of `Good`.

The current global-envelope situation is asymmetric:

* `APrimeQVGlobalPoly.eventually_qvAt_le_poly` is an all-sample polynomial
  envelope for the actual uncut `Q_r`.
* `Gauss.exists_bdd_uker_driftF` and
  `APrimeSmoothWeightActual.exists_prefixMatrix_fderiv_bound` only give
  fixed-finite-`N` bounds; the latter is private.  No exported theorem gives
  a fixed polynomial degree, uniform in the first-cell prefix, for the
  actual drift or for `B_k`.
* Consequently no current theorem supplies the required global polynomial
  envelope for the full product `B_k sqrt(Q_r)`.  This is the exact missing
  complement input.  Splitting only `Q_r` does not repair it.

## 5. `crossAt` versus the full cross profile

T440 uses

```text
Bcr(r) = APrimeDriftTimeFamily.crossAt 0 0 v kappa r
       = sqrt(r)^(-1) sqrt(kappa * qHatNear 0 0 v r).
```

To feed T361 into this exact `Bcr`, one still needs, for every `r in (0,v)`,

```text
Cs(Pmom)/(4 Pmom)
  * (b(r) sqrt(q(r)) + Eall(r) rho^(1/(2Pmom)))
 <= sqrt(kappa * qHatNear 0 0 v r).
```

No current declaration proves this.  In particular the actual current QV
contains the quadratic and cubic far rows, while `qHatNear` is the normalized
near row.  T405 pays the far rows after the full time integration; that does
not imply the displayed pointwise comparison.

Thus the near-only `crossAt` may not be installed as the actual `hcross`
budget by renaming the T361 conclusion.  The sound T405 alternative is to
take `B=Bfull`, prove `IntervalIntegrable Bfull`, and prove the corresponding
`A+Bfull` and prefix-product integrability statements.  Its early/late split
is:

* integrate `r^(-1/2)` directly while `r<=1/2`;
* on the later part use Cauchy--Schwarz and the identity
  `eta_s^(-1) integral_s^v dr/r <= 2/m0`.

That route has no `log(1/s)` loss and remains valid at the first cell.

## 7. The zero-time endpoint

There is no singular pointwise obligation at `r=0`:

* `weightedMinkowski_of_deriv_le` asks for `hbound` only on `Ioo 0 v`;
* `hasDerivAt_momFlow` also asks for positive time;
* `APrimeCrossJointSplit.crossPart_zero_r0` proves the actual cross part is
  zero at `r=0`;
* `crossAt ... 0=0` by the totalized inverse, and the full profile is handled
  by its integrable `r^(-1/2)` majorant;
* continuity of the weighted moment supplies the closed endpoint.

The stored prefix at `j=0` has the literal pullback factor `sqrt(0)=0`, so
its contribution to the prefix covariance gradient is zero.  This must not
be confused with the initial coordinate: `Y_0` is generally nonzero.  Its
moment is the independent T280e/`BoundsCore` initial input, not a zero term.
For `k=0`, `weightD_zero_k0` and `crossPart_zero_k0` give the separate empty
prefix branch.

## 8. Quantifier order and same-measure Lyapunov

The required order is compatible with the first-cell producers:

```text
choose tau' once;
for every 0 < delta <= delta0;
for every requested p;
choose a fixed high order Pmom >= p and large enough for the family cardinality;
choose the source losses and the Good^c failure exponent after Pmom and the
  fixed polynomial envelope degrees;
then, eventually in N, prove the bounds simultaneously for every k and a.
```

`Pmom` and the exceptional-probability exponent are fixed before the
`eventually N` statement.  They may not depend on `N`, `k`, `a`, or the
running time.  T434's `sharpCommonEvent` is measurable and high probability
and is already uniform in the real running time; it does not depend on the
output label.  The final estimate must retain `forall k <= cutNetTop` and
`forall a` after the same eventual threshold.  The `p=0` family row is
proved directly from `0<=W<=1`; it does not enter `momFlowDeriv_le`.

T405's Lyapunov step is mathematically correct only under one fixed
subprobability measure.  The compiled theorem is
`APrimeInit.momNormW_le_momNormW_of_exponent_le`.  The valid use is:

1. choose `Pmom>=p`;
2. prove the high moment with the single smooth weight
   `wHigh=c_k^(2Pmom)`;
3. apply weighted Lyapunov from `Pmom` to `p` with the same `wHigh`;
4. dominate the requested old/widened target weight by `wHigh` pointwise.

One must not compare a moment under `c_k^(2p)` with a moment under
`c_k^(2Pmom)` by Lyapunov.  The existing
`widenedW_le_weight_canonical` only compares equal order parameters.  For
`p>=1`, its support argument does prove the stronger cross-order statement

```text
widenedW(..., p, ...) <= actualSmoothWeight(..., Pmom, ...),
```

because a nonzero widened weight forces the new cutoff to equal one; where
the widened weight is zero the inequality is trivial.  This cross-order
version is not currently exported.  It is false at target `p=0` with
`Pmom>0`, which is why the zero-order row must remain separate.
