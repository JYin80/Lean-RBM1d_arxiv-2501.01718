## Verdict: FAIL for the claimed mathematical obstruction; direct signature mismatch confirmed

T1125 correctly found that the **public statement** of
`APrimeGeneralMovingHighQK0Repair.eventually_selected_high_k0` does not return
the input order. Applied at T1119's selected `q`, it returns some `q₀ ≥ q`.
The equality `q₀ = q` in T1097's proof (`refine ⟨p, le_rfl, ...⟩`) is not part of
that theorem's public contract. Thus the prescribed direct instantiation in
the T1125 ticket cannot identify its two literal integrands. T1125 complied
with the ticket's instruction to stop on an exact signature mismatch.

The stronger assertion in T1125 that these **public producer results alone
cannot yield** the requested common-order two-point estimate is false. At
`k = 0`, `cutNetPt ... 0 = s N` and the prefix is empty. By the public
definition of `widenedW` (and the calculation in T1097's source), its weight
is exactly `1` for every order. Put

`X_N = cutTrunc (N^(2δ)) (jSnorm(sample d, E, D, s, N, s N))`.

T1097 applied with input `p = q` gives, eventually,

`E[|X_N|^(2q₀)] ≤ C₀ N^(δq₀/2)` for some `q₀ ≥ q` and `C₀ > 0`.

Because `B.P` is a probability measure, the moment monotonicity (Lyapunov)
inequality gives

`E[|X_N|^(2q)] ≤ E[|X_N|^(2q₀)]^(q/q₀)
                 ≤ C₀^(q/q₀) N^(δq/2)`.

The cutoff is bounded and measurable at each positive `N`, so the relevant
moments are integrable. The repository already proves this exact exponent
transfer in `APrimeGeneralMovingLowMomentTransfer.low_integral_of_high_integral`
(starting at line 131), with `χ = 1`. Since T1119 independently supplies the `k=1`
bound at its selected `q`, the two eventual statements can then be combined
with a positive constant such as `C₁ + C₀^(q/q₀)`. This is a mathematical
derivation from the public contracts and existing generic tools, not a
verified Lean composition. No T1125 or T1126 two-point theorem exists.
