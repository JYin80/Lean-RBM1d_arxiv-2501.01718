# T625 — dependency-boundary preflight for the T620/T624 drift-slot route

## Verdict

T624 is **not dispatchable**.  This is not merely the direct
`APrimeSlotArith -> APrimeModel -> Flow.Step345Producer` cycle already recorded in T620:
the present T615 producer itself has independent transitive paths to
`Flow.Step345Producer`, `Hierarchy.Step3`, `Flow.FirstCell`, `APrimeOneStep`, and
`APrimeAssembly`.  Importing the three modules proposed by T620 therefore cannot produce a
pre-Step-3 leaf.

The sharp T620 exponent ledger is retained unchanged.  Its future public theorem must,
however, be an **envelope** theorem, not the actual-`g` theorem proposed in the superseded
part of T620.  For every cell it must first expose

```text
IntervalIntegrable (fun u => profile ... u + N^(-beta)) volume s_N v
2 * integral[s_N,v] (profile ... + N^(-beta)) <= slotDrift ... / 2.
```

Only then may it derive the fixed-`Step2.sigPM` actual-`g` corollary from T615's
`g <= profile + N^(-beta)`.  The reverse implication is false: a small integral of `g`
under the pointwise inequality `g <= Qbd` does not bound the integral of `Qbd`.
This is exactly the direction required by `APrimeOneStep.drift_bound_of_envelopes`, whose
`htime` premise integrates `Qbd + Cbd`.

One bounded extraction cannot clear the boundary: there are independent scalar-consumer,
calculus/time-family, smooth-weight/event, global-poly, and weighted-norm ingress paths.
The first honest file-disjoint successor is the scalar consumer-core extraction specified
in [Selected first ticket](#selected-first-ticket).  The half-slot implementation remains
blocked until a subsequent closure audit finds none of the forbidden modules.

This audit was read-only except for this report.  It was performed at Git HEAD `653879c`
with the dirty working tree left untouched; the withdrawn, untracked partial
`RBM1D/Gauss/APrimeGeneralMovingSmoothDriftSlot.lean` was inspected but excluded from every
admissible dependency claim.

The sole paper source was `paper/250520-YinJun-v2.pdf`, SHA-256

  not import or silently use that conclusion.

The sharper pre-compression T598/T615 decomposition remains the only admissible basis for
the deterministic integration.  With `deltaCap = deltaWeight + xi`, retain verbatim

```text
eNear = zetaCtr + zetaSrc + rho,
eFlow = zetaCtr + tauG + 2 deltaCap + rho,
eFar  = zetaCtr + (3/2)(tauG + 2 deltaCap) + rho,
eQuad = 4 deltaCap + rho.
```

The four principal rows and strict margins remain

| Row | Integrated upper bound | Required margin |
|---|---|---|
| near | `C N^eNear R_v^-2` | `eNear < deltaSlot/4` |
| flow | `C R_v^-2 N^eFlow R_t^(5/2) A_t^(-1/6)` | `eFlow/c + (5/2)/30 < 1/6` |
| sharp far | `C R_v^-2 N^eFar R_v^(9/2) A_v^-1` | `eFar/c + (9/2)/30 < 1` |
| quadratic | `C R_v^-2 N^eQuad R_v^6 A_v^-1` | `eQuad/c + 6/30 < 1` |

No residual may be dropped.  The retained estimates are the near tail
`C N^(eFlow+2) W^(-D) R_v^(5/2)`, the `W^-1` far sibling, the far spatial
leakage with exponent `eFar + 1 + 3/20 - 5D/16`, and the quadratic floor with
exponent `eQuad + 1 + 1/5 - 5D/8`.

Two corrections are mandatory in the eventual implementation.

1. `Cond272Reg` contains `c > 0` only through a separate hypothesis and the eventual lower
   bound `N^c <= A_t`; it does **not** contain `c <= 1`.  Any use of that inequality in the
   residual arithmetic must either be removed or be supplied by an upstream lemma for
   `Dims.exampleGrow`.  Such a lemma can combine, at one eventual `N >= 2`,
   `N^c <= A_t`, the existing elementary bound `A_t <= N`, and monotonicity of real powers
   to infer `c <= 1`.  The proof must not add `c <= 1` to `Cond272Reg` or change its frozen
   signature.
2. T615's `g` hard-codes `Step2.sigPM`.  Its `a : LoopArg (d.L N) 2` is the output label,
   not a charge word.  The successor is uniform in `a` but is not an arbitrary-charge
   theorem.

The quantifier order remains `p`, then `beta`, then `forall^eventually N`.  Both closed time
endpoints are retained.  The `k=0` cell must be discharged only by `cutNetPt_zero` and
`intervalIntegral.integral_same`, never by applying a positive-cell pointwise estimate.

## Smallest signature-preserving extraction plan

All moved declarations must keep their present fully qualified names, namespaces,
arguments, quantifier order, theorem statements, and axiom sets.  Existing public modules
become compatibility facades by importing the core and deleting only the duplicate bodies;
no alias, primed replacement, deprecation, or frozen-signature change is needed.

The minimal safe order is:

1. **Scalar consumer core (selected first).**  First extract `StepSideAPrime.cWt` and
   `cWt_pos` below `Step2MomentStep`, then extract the three algebraic one-step terms and
   the drift-only slot prefix.  This removes `APrimeModel`, `Flow.Step345Producer`,
   `Flow.FirstCell`, and `Hierarchy.Step3` from the literal `slotDrift` surface without
   touching T627's `APrimeSmoothPrefix.lean` ownership.  Importing the current

   calculus core; move `Cond272Reg` and `toCond272` to a hypothesis core; move the generic
   `driftScale`/`driftAt` continuity and integrability declarations to a time-family core.
   The current files import these cores as compatibility facades.
3. **Producer cores.**  Split witness-free common-source/profile/global-poly declarations,
   generic weighted-event norm lemmas, actual smooth-weight declarations, and QV kernel
   inequalities from their first-cell/assembly wrappers.  Leave every positive witness in
   its downstream wrapper.  T627's clean `APrimeSmoothPrefix` result must be used rather
   than edited concurrently.
4. **T615 core.**  Move the exact definitions, integrability, pointwise comparison, and
   direct-integral theorem into
   `APrimeGeneralMovingSmoothDriftNormBudgetCore.lean`, importing only the cores from steps
   2--3.  Keep `positive_first_cell_budget_hypotheses_witness` in the old facade.
5. **Closure audit, then envelope half-slot.**  Recompute the transitive graph.  Only if the
   future half-slot module has no path to `Flow.Step345Producer`, `Hierarchy.Step3`,
   `Flow.FirstCell`, `APrimeModel`, `APrimeOneStep`, or `APrimeAssembly` may it be dispatched.

Combining steps 2--4 into one ticket would require coordinated edits across independent
first-cell, event, smooth-weight, QV, time-family, and T615 files and would not be a bounded
extraction.  The ordered split is therefore necessary.

## Correct future envelope API

After all extraction steps and the clean-closure audit, the first public mathematical
theorem must have the following logical shape (names abbreviated only here):

```text
forall^eventually N, forall k <= cutNetTop ..., forall a,
  IntervalIntegrable (fun u => profile ... u + N^(-beta)) volume s_N endpoint_k
  /\
  2 * integral[s_N,endpoint_k] (profile ... + N^(-beta))
    <= slotDrift (Im mE) (N^(deltaSlot/8)) R_endpoint / 2.
```

The integrand is independent of `a`; retaining `forall a` is useful only for the immediate
corollary matching T615's actual `g`.  That corollary may state integrability of `g` and

```text
2 * integral g <= slotDrift ... / 2
```

by interval-integral monotonicity.  It must be clearly labelled as the fixed-`sigPM`
corollary, not the premise used to bound the envelope.  The future consumer will combine
the envelope with a separately produced cross envelope `Cbd`; it must not call the drift
slot closed before that cross half exists.

`c > 0`, window `s_N = 0 < t_N` eventually, `Cond272Reg`, `BoundsCore`, active cell `k=1`,

positive actual weight at `deltaWeight` to positive canonical widened support at


The witness also keeps `deltaWeight` and `deltaCap` genuinely distinct.  It validates the
future theorem's assumptions and positive interval.  It does not validate an
arbitrary-charge claim, a cross term, a QV term, a Step-3 conclusion, `hfamily`, a universal
`APrimeSlot'`, or the six-step chain.
