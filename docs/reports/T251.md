## ⭐⭐ 最重要的结论：`s ≡ 0` 那一格**确实需要**，而这条链**供不出来**

p.24 的归纳是 `boundsGrid_of_fields`（`Flow/EnergyUniform.lean:432`）：从 `hzero : P (fun _ => 0)` 起，对**每一对**相邻格点 `(u_k, u_{k+1})` 施加 `hstep`，**`k = 0` 包含在内**，而 `u_0 ≡ 0`（`gridT_zero`）。所以 `Thm221NoEL.step` **真的在 `s ≡ 0` 处被调用**，而 T249 已证 (5.48)/`CutHypEv` 的 `modulus` 在那里为假。

两条编译的证书把这件事钉死：
* `not_windowLeft_gridT_zero` —— 第 `k = 0` 格**永远**不满足 `WindowLeft`（对**任何** `C`，不只是 `C > 0`）；
* `windowLeft_gridT_succ` —— 每个 `k ≥ 1` 格都满足，只要 `t` 最终被一个正常数从下界住（`1 − W^{−τ'} → 1` 由 (2.2)，`N^{−C} → 0`）。

**于是 (A′)/(5.48) 这条链必须改起点**，合并总装的结论从 `Thm221NoEL X κ` **降为 `Thm221NoELFrom X κ C`**。残项被精确陈述为 `thm221NoEL_of_from` 的第二个参数：左端点不最终 `≥ N^{−C}` 的那些步——在 p.24 网格里就是**唯一的一格 `u_0 = 0 → u_1`**。
