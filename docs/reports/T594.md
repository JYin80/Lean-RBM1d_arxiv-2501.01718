# T594 — smooth/widened support mismatch after T584 and T587

## Scope and primary verdict

This is a read-only mathematical/Lean preflight.  No Lean source, scheduling
document, root import, commit, or remote state was changed.  This report is the
only deliverable.

**Primary verdict: incomplete, with one smallest valid support bridge.**  At the
same cutoff exponent `delta`, the implication

```text
0 < APrimeSmoothWeightActual.weight  ->  0 < APrimeWeight.widenedW
```

is false.  The compiled comparison has the opposite direction,

```text
widenedW(delta,p) <= actualWeight(delta,p),
```

and this direction is exactly the one needed only at the *endpoint moment*
transfer.  It cannot localize T584 on the support of the differentiable weight.

The smallest honest repair does not change the differentiable cutoff.  For every
fixed `xi > 0`, positive support of the existing actual smooth weight at `delta`
is eventually contained in positive support of the old widened weight at
`delta + xi`, uniformly in every active prefix and on the same sample.  The loss
is precisely `N^(2*xi)` in the support threshold.  T584 may then be invoked with
`deltaCap = delta + xi`, while the generator and the endpoint moment continue to
use the actual weight and target widened weight at `delta`.

This is a deterministic cutoff bridge.  It assumes no common event and no
moment conclusion, so it is acyclic with respect to T584, `hfamily`,
`APrimeSlot'`, and the six-step assembly.

## Why the same-`delta` implication is false

The cutoff geometry already shows the mismatch.  At the old widened support
boundary

```text
H = 4 * exp(1) * N^(2*delta),
```

the widened cutoff has argument `2`, so it is zero.  On the other hand, each
stored hard value is at most its hard soft maximum `H`, so the actual comparison
estimates give

```text
S <= exp(1) * (H + N^(-10))
  <= (4*exp(1)^2 + exp(1)) * N^(2*delta)
  < 8*exp(1)^2 * N^(2*delta) = threshold(delta,N)
```

for `N >= 1` and `delta >= 0`.  Hence the actual cutoff is exactly one there.
So one can have

```text
actualWeight(delta,p) = 1,
widenedW(delta,p)     = 0.
```

This scalar configuration occurs in the actual Gaussian model, not only in an
abstract cutoff toy.  Use the positive first-cell ray from the T329
falsification check: at the zero scalar sample the fixed positive-prefix hard
soft maximum is `O(1)`, while along the supported Hermitian ray `X=t I` it
eventually exceeds a constant times `W`.  For the growing model and, for
example, `0 < delta < 1/4`, `W/N^(2*delta) -> infinity`.  Continuity therefore
gives a finite point of the ray where the hard prefix equals the displayed
boundary.  The upper estimate above puts the actual smooth cutoff on its
plateau at that same sample, while the widened cutoff is zero.  This refutes a
universal same-`delta` reverse-support theorem.  It does not use a first-cell
statement as a general-moving producer; a single admissible first-cell
specialization suffices to refute the universal implication.

## The one dispatch-ready theorem

The cheapest useful statement belongs in a new neutral module importing
`APrimeSmoothWeightActual`; it should not import any first-cell QV module.  The
following is the **only** theorem recommended by this ticket.

```lean
theorem eventually_actualWeight_pos_implies_widenedW_pos
    (d : Gauss.Dims)
    {E D delta xi : Real} {s t mesh : Nat -> Real}
    (hE : |E| < 2)
    (hst : forall N, s N <= t N)
    (ht1 : forall N, t N < 1)
    (hmesh : forall N, 0 < mesh N)
    (hxi : 0 < xi)
    (p : Nat) (hp : 1 <= p) :
    ∀ᶠ N : Nat in Filter.atTop, forall k : Nat,
      k <= CutHypTheta.cutNetTop s t mesh N ->
      forall omega : Gauss.Ω d,
        0 < APrimeSmoothWeightActual.weight d E D delta s t mesh
          2 p N k (APrimeSmoothWeightActual.canonicalM d s t mesh N) omega ->
        0 < APrimeWeight.widenedW
          (APrimeWeight.canonicalR s t mesh) 1
          (fun N u omega =>
            Step2Moment.jSnorm (Gauss.sample d) E D s N u omega)
          s t mesh (delta + xi) p N k omega
```

No `Cond272Reg`, common event, `BoundsCore`, or stochastic hypothesis belongs in
the statement.

### Proof ledger and exact inequalities

Fix an eventual `N >= 2`, an active `k`, and the same `omega` as in the
premise.  Put

```text
S = prefixSample(..., canonicalM ..., omega),
H = softMax(canonicalR ..., range k, hard jSnorm values),
thetaWide = 2 * exp(1) * N^(2*(delta+xi)).
```

1. Since `p >= 1`, positivity of `actualWeight` implies its base cutoff is
   nonzero.  Since `cutChi x = 0` for `2 <= x`,

   ```text
   S < 2 * threshold(delta,N)
     = 16 * exp(1)^2 * N^(2*delta).                       (1)
   ```

2. For every `j < k`, the window hypotheses give
   `s_N <= u_j <= t_N < 1`.  The regularization is positive and
   `canonicalM >= 1`, so

   ```text
   jSnorm(u_j) <= smoothJS(u_j) <= S.                     (2)
   ```

   The first inequality is `APrimeSmoothPrefix.jSnorm_le_smoothJS`.  The
   second is the defining outer soft maximum and
   `Step2Bootstrap.le_softMax`.  It uses the identical matrix/sample and net
   time; there is no change of event or sample.

3. `APrimeWeight.card_calib_top` for `canonicalR` and
   `Step2Bootstrap.softMax_le`, together with nonnegativity of `jSnorm`, give

   ```text
   H <= exp(1) * S
     < 16 * exp(1)^3 * N^(2*delta).                       (3)
   ```

4. Because `xi > 0`, eventually

   ```text
   4 * exp(1)^2 < N^(2*xi).                               (4)
   ```

   Combining (3)--(4),

   ```text
   H / (2 * exp(1) * N^(2*(delta+xi))) < 2.               (5)
   ```

   The positivity of `cutChi` below `2` is proved by the same elementary
   two-branch calculation already used in the first-cell code: it is `1` at
   arguments at most `1`, and on `(1,2)` its factorization is a product of two
   positive factors.  This scalar proof should be placed privately or in the
   neutral cutoff module, not imported from a first-cell module.  Equation (5)
   makes the widened cutoff positive, and its `2*p` power remains positive.

There is no hidden `W` or time-ratio loss in this bridge.  The regularization
`epsilon = W^(-D) N^(-10)` has already become the additive `N^(-10)` in the
compiled hard/smooth comparison, and `N^(-10) <= N^(2*delta)` for
`N >= 1`, `delta >= 0`.  The only new asymptotic factor is `N^(2*xi)`.

## How the bridge is consumed, with every direction fixed

For a generator calculation at target exponent `delta`:

```text
piecewiseW(delta)
    <= widenedW(delta,p)
    <= actualWeight(delta,p)                              endpoint direction

actualWeight(delta,p) > 0
    -> widenedW(delta+xi,p) > 0                           support direction

T584 at delta+xi
    -> qvAt <= Qexact(delta+xi)                            profile direction
```

The first line transfers an estimate already proved under the differentiable
actual weight down to the endpoint widened/piecewise moment.  The second line
is used only to justify T584 at a sample where the generator integrand is
nonzero.  No numerical comparison between `actualWeight(delta)` and
`widenedW(delta+xi)` is required.

Consequently the literal T584 cap becomes

```text
1 + N^tauG *
  (9*exp(sqrt 3) *
    ((4*exp(1)+2) * N^(2*(delta+xi)) * ratR(E,s,N,u)^4) + 2),
```

and its applicability room is exactly

```text
tauG + 2*(delta+xi) + 2/15 < 1.
```

All other T584 powers are unchanged: `sourceEll`, `sourceC4`, `W^(-1)`, the
two `W^(-D)` leakages, `ratR_u^(-2) ratR_v^(-2)`, and the square of the whole
root profile remain literal.  A later actual-weight analogue of T591 must
therefore keep two distinct parameters: `deltaWeight = delta` in `rateNormW`
and `deltaCap = delta+xi` in `Qexact`.  Identifying them would recreate the
support error.

`momFlowDeriv_le` then uses the actual-weight QV rate, and
`weightedMinkowski_of_deriv_le` integrates that same rate.  On samples where
the weight is zero, the QV integrand is zero.  On the strict transition used
by `weightD`, the cutoff is positive, so the same bridge supplies the support
needed by the QV factor in the cross estimate.  Off the transition the
compiled derivative-zero branches apply.

## Quantifiers and boundary audit

- `delta`, `xi`, and `p` are fixed before the eventual threshold in `N`.
  The threshold may depend on all three.  Uniformity is then over every active
  `k` and every sample `omega`.
- `p >= 1` is essential for reading positivity of a power back to positivity
  of its cutoff.  The final `p=0` moment is trivial and must remain a separate
  branch; T584 and Minkowski are not called there.
- At `k=0`, both prefix soft maxima are empty and both weights equal one.
  The theorem is true there without a pointwise QV claim.  Any integrated QV
  consumer must still use `v_0=s_N` and the zero-length integral, as T587 and
  T591 do.
- At `k=cutNetTop`, every stored index satisfies `j<k`, so its time is still in
  `[s_N,t_N]`; the proof does not lose the active endpoint.
- Sizes `N<2` are irrelevant to the eventual theorem.  Taking `N>=2` makes
  both piecewise branches active and supplies `canonicalM>=1` and positive
  regularization.
- The bridge has no event parameter.  It is applied to the exact `omega` in
  T579's common event, so the source, QV profile, smooth weight, and hard
  widened support all refer to the same sample.

## Differentiability and the proposed modified-cutoff alternative

The existing actual weight remains the correct differentiable localization:
`weightC1` is already compiled, and the bridge changes neither `weight` nor
`weightD`.  Therefore no new derivative formula, derivative bound, finite
dependence proof, or integrability argument is introduced.

At the literal same `delta`, the existing cutoff cannot have support contained
in `widenedW`; the counterexample above has actual weight one and widened
weight zero.  A newly designed same-`delta` differentiable cutoff is not a
dispatch-ready replacement.  To dominate the endpoint widened/piecewise
moment while keeping its support inside the old widened support, it would need
a new two-sided, pointwise hard/smooth-prefix calibration through the whole
transition profile (and, because of the `2p` power, calibration depending on
the moment order).  The repository has only the coarse factor-`exp(1)` upper
calibrations and the one-way plateau theorem; these do not prove such a
construction.  Rebuilding `WeightC1` and the cross-gradient rate for a new
cutoff is strictly larger than the support bridge above.

With an arbitrarily small fixed `xi>0`, however, the *existing* differentiable
weight does satisfy the useful buffered version: it dominates the endpoint
weight at `delta`, while its support is contained in widened support at
`delta+xi`.  This is the strongest safe conclusion of the audit.

## Nondegenerate satisfiability and noncircularity

The bridge is nonvacuous on the same positive-duration first-cell resident
already used by T584.  Take `E=0`, `D=60`, `p=1`,
`delta=xi=1/100`, the positive first target cell, and T584's same-event resident.
That witness gives widened weight one at `delta`;
`widenedW_le_weight_canonical` together with `weight_le_one` then gives actual
weight one on the same sample.  Increasing the widened exponent to `delta+xi`
only enlarges its threshold, so the conclusion is also weight one.  The room
remains

```text
1/100 + 2*(1/100+1/100) + 2/15 < 1.
```

The proposed proof uses only cutoff algebra, finite soft-max comparisons,
the hard-to-smooth pointwise comparison, and eventual absorption of a fixed
constant by `N^(2*xi)`.  It does not use `hfamily`, any weighted-moment
conclusion, `APrimeSlot'`, the general drift/cross/QV generator, or a later
bootstrap conclusion.
