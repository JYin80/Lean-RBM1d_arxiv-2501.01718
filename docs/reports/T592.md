# T592 — preflight for the general-moving actual cross bridge

## Verdict

There is no honest direct general-moving `crossPart` theorem ready to dispatch
from the present T584/T586 surfaces.  The first missing implication is a
support bridge, not another cross-term inequality:

```text
same omega in commonEvent and the actual smooth transition
  ==> a running jSnorm cap on [s_N,v_k].
```

The compiled comparison goes only in the direction

```text
target widenedW <= actual smooth weight,
```

so positivity of the actual smooth weight (or membership in its strict
transition band) does **not** imply positive target `widenedW`.  Consequently
T584's evolved-QV profile and T586's supported drift bounds cannot be applied
on the whole transition support of the actual derivative.  Reversing this
comparison would be invalid.

The single smallest dispatch-ready public theorem is stated in the next
section.  It should be proved before attempting a general-moving
`crossPart_active_le_jointEvent` specialization.  This report makes no claim
that (5.35), (5.42), a full cross budget, `hfamily`, `APrimeSlot'`, stopping,
BDG, the six-step chain, or the paper is closed.

No Lean source, scheduler document, root import, commit, or remote state was
changed.  This report is the only T592 artifact.

## The one recommended theorem

Add a module such as
`RBM1D/Gauss/APrimeGeneralMovingSmoothTransitionSupport.lean`.  Keep the
existing private specialization

```text
d = Dims.exampleGrow,    B = band d,
mesh = APrimeGeneralMovingMesh.targetMesh D.
```

The only public target should be the following proposition (minor namespace
or local-abbreviation changes are harmless, but not its quantifier order,
event, transition, interval, or constant):

```lean
theorem eventually_running_cap_on_smooth_transition
    {E D c delta zetaSrc zetaCtr tauG : Real}
    {s t : Nat -> Real}
    (hE : |E| < 2) (hD : 60 <= D)
    (hs0 : forall N, 0 <= s N)
    (hst : forall N, s N <= t N)
    (ht1 : forall N, t N < 1)
    (hc : 0 < c)
    (hreg : Cond272Reg B E s t c)
    (hdelta : 0 < delta) :
    forall eventually N : Nat in Filter.atTop, forall k : Nat,
      1 <= k ->
      k <= CutHypTheta.cutNetTop s t
        (APrimeGeneralMovingMesh.targetMesh D) N ->
      forall omega in
        APrimeGeneralMovingCommonSources.commonEvent
          E D s t zetaSrc zetaCtr tauG N,
      omega in APrimeCrossJointSplit.transition d E D delta s
        (APrimeGeneralMovingMesh.targetMesh D) N k
        (APrimeSmoothWeightActual.canonicalM d s t
          (APrimeGeneralMovingMesh.targetMesh D) N) ->
      forall u in Set.Icc (s N)
          (CutHypTheta.cutNetPt s
            (APrimeGeneralMovingMesh.targetMesh D) N k),
        APrimeGeneralMovingDetFields.J E D s N u omega <=
          (16 * (Real.exp 1)^2 + 1) * (N : Real)^(2 * delta)
```

Here `forall eventually` and `forall ... in ...` display the intended
`∀ᶠ`/membership binders; the implementation may of course use the repository's
usual Lean notation.

This is smaller than a QV-profile or cross theorem.  It contains neither
`BoundsCore` nor positivity assumptions on `zetaSrc,zetaCtr,tauG`, because the
proof only extracts the norm-event component from an already given
`commonEvent` resident.  It contains no `p`, `N0`, `sigma`, `a`, `v`, or `r`,
because the actual transition and the running normalized-loop cap do not
depend on them.  Adding those unused parameters would obscure the first
logical seam.

### Exact proof route

The proof is upstream and noncircular.

1. Generalize the private content of
   `APrimeSmoothTransition.jSnorm_net_le_prefixSample` from its hard-coded
   `E=0,s=0` to arbitrary `E,s`.  The required analytic statement is already
   `APrimeSmoothPrefix.jSnorm_le_smoothJS`; the remaining step is the finite
   soft maximum and `smoothJSMatrix_flow`.  This generalization may remain a
   private helper in the new module.
2. Membership in `transition` gives the strict upper bound

   ```text
   prefixSample < 2 * threshold
                = 16 * exp(1)^2 * N^(2*delta).
   ```

   Thus every stored net value with index `j<k` has this same upper bound.
3. From the same `omega in commonEvent`, use
   `commonEvent_subset_rawCarrier` and
   `sourceGood_subset_good` to obtain membership in
   `APrimeGeneralMovingGoodMesh.good N`.  Apply the existing general-moving
   `jSnorm` modulus and mesh-fineness estimate to propagate from a preceding
   stored net point to every `u in [s_N,v_k]`, at cost at most `1`.
4. Eventually `N>=1`; since `delta>0`, `1 <= N^(2*delta)`.  Absorb that modulus
   cost to obtain exactly

   ```text
   (16 * exp(1)^2 + 1) * N^(2*delta).
   ```

The proof uses no target-weight support, no desired moment estimate, no
`hfamily`, no `APrimeSlot'`, no stopping argument, and no later cross/QV
consumer.  Its dependency direction is therefore suitable for later replay
of the T584/T586 source arguments on `commonEvent ∩ transition`.

The theorem is conditional on an actual transition resident, as every
pointwise transition estimate is.  The underlying moving-window/common-event
hypotheses are nondegenerate by T579's positive first-cell witness.  Existing
first-cell files also prove that the actual smooth cutoff is genuinely
nonconstant and has strict-transition samples, but no current declaration
places such a sample in this exact general-moving `commonEvent`.  The proposed
theorem must not claim that additional intersection witness.  Conversely,
its proof and usefulness for the event split do not require inventing one:
`crossPart_active_le_jointEvent` already treats only samples that lie in the
intersection and pays the complement separately.

## Why the existing cross consumers do not close the seam

### `APrimeCrossJointSplit`

The actual producer is
`crossPart_active_le_jointEvent`.  Its literal active variables are

```text
d : Dims;
E,D,delta : Real;
s,t,mesh : Nat -> Real;
N0,N,k,m,p : Nat;
sigma : Fin 2 -> Bool;
a : LoopArg (d.L N) 2;
v,r : Real.
```

It assumes `|E|<2`, `s_N<1`, `0<=s_N`, `v<1`,
`r in [s_N,v]`, **`0<r`**, `0<N`, `1<=m`, all stored net times below one,
an active prefix, `N0<=N`, and **`1<=p`**.  On one measurable `Good`, the
two favorable estimates are required on the same literal set

```text
Good ∩ transition d E D delta s mesh N k m.
```

The conclusion uses the actual derivative

```text
APrimeSmoothWeightActual.weightD ... N0 p N k m
```

and has the exact factor

```text
(1 / (2 * sqrt r)) * (2*p)^2 * (15/8)
```

times the coordinate-moment power and

```text
b * sqrt q + Eall * rho^(1/(2*p)).
```

Thus the positive-time singularity and its coefficient are already correct;
they must not be replaced by a bound lacking `(2*sqrt r)^(-1)`.  The theorem
also explicitly requires measurability of `Good`, measurability of the two
Holder factors, integrability of their `2p` powers and product, a global joint
envelope, and a complement-probability bound.  T584/T586 do not themselves
supply this complete regularity package.

The boundary declarations in the same module are also exact:

- `p=0`: `weightD_zero_p0` and `crossPart_zero_p0`;
- inactive prefix: `weightD_zero_inactive` and
  `crossPart_zero_inactive`;
- `k=0`: `weightD_zero_k0` and `crossPart_zero_k0`;
- `r=0`: `crossPart_zero_r0`.

Accordingly a future time-integrated theorem must split `r=0` from `r>0`;
the pointwise singular formula is only for `r>0`.  The `k=0` time cell has
equal integration endpoints and zero cross term, but an instantaneous QV rate
need not vanish there.

### `APrimeDuhamelModel`

`crossPart_le_of_S5` is not a substitute for the joint transition theorem.
It requires

```text
wD q omega = 0    for every omega outside Good.
```

The actual smooth-weight derivative vanishes outside its transition band,
not outside T579's stochastic `commonEvent`.  Taking
`Good = commonEvent` would therefore add a false unsupported premise.

`crossBudget_le_crossInt_model` is only arithmetic.  With `u>0`, `uj<=1`,
`p>=1`, `Cs0>=0`, and `(Cs0/(4p))^2<=kappa_h`, it compares

```text
(Cs0 * sqrt(uj/u)) * sqrt(Qh u) / (4p)
```

with `crossInt`.  It produces neither the actual S5 bound nor a same-event
evolved-QV estimate.  In particular, it cannot supply the missing support
implication.

### `APrimeDriftTimeFamily` and `APrimeBadSplit`

`NearCrossBridge` is only a proposition defining a desired inequality.  It
hides the positive-time restriction, S5 hypothesis, evolved-QV estimate,
same-event split, far/residual rows, and all measurability/integrability
obligations.  It is not a producer and must not be assumed.

`APrimeBadSplit.crossPart_le_of_S5_event` is a valid generic event split, but
it assumes a global S5 inequality and a global evolved-QV envelope.  It does
not connect the actual smooth derivative to T584's target-weight-localized
profile.  Its algebraic budget corollary therefore starts downstream of the
same missing support seam.

## T584/T586 and the three weight notions

T584 and T586 are fixed at `d = Dims.exampleGrow` and use T579's same
`commonEvent`.  Their supported theorems assume

```text
0 < APrimeWeight.widenedW
      (APrimeWeight.canonicalR s t (targetMesh D)) 1
      (APrimeGeneralMovingDetFields.J E D s)
      s t (targetMesh D) delta p N k omega.
```

This is the **target widened weight**.  Its order parameter is `2p`, its hard
cutoff scale is based on `2*exp(1)*N^(2*delta)`, and its stored functional is
the actual `jSnorm`.

The cross producer instead differentiates the **actual smooth weight**

```text
APrimeSmoothWeightActual.weight ... m,
```

with smoothing order

```text
m = APrimeSmoothWeightActual.canonicalM d s t mesh N
  = cutNetTop s t mesh N * card(LoopArg (d.L N) 2) + 1
```

and threshold

```text
8 * exp(1)^2 * N^(2*delta).
```

The **canonical target order** `canonicalR = cutNetTop+1` belongs to
`widenedW`; it is not `canonicalM`.  These parameters must not be identified.

The available comparison
`APrimeSmoothWeightActual.widenedW_le_weight_canonical` proves

```text
widenedW(canonicalR,...) <= smoothWeight(canonicalM,...).
```

Hence

```text
widenedW > 0  ==>  smoothWeight > 0,
```

but not conversely.  The strict smooth transition does imply positive smooth
weight, yet gives no positive target widened weight.  This is precisely why
T584/T586 cannot simply be invoked under the cross producer's transition
hypothesis.

T584's exact QV output should otherwise be retained.  It is on every closed
prefix time `u in [s_N,v_k]` and keeps

```text
qvAt <= (driftScale^-1 * rootProfile(...))^2,
```

with the moving `ratR^4` cap, the quadratic and cubic rows, spatial leakage,
near `2*W^(-1)` repair, and endpoint kernel powers.  It is not the simplified
paper (5.42) monomial.  T586 similarly retains the exact (5.35) far rows and
an explicit near residual; it does not prove the simplified or integrated
paper estimate.  Neither result may be silently weakened into a different
`N`, `W`, or time power and then advertised as (5.35)/(5.42).

## Paper normalization and later cross arithmetic

In the paper, (5.35) has the displayed near term

```text
eta_u^(-1) * (ell_u/ell_s)^2 * 1(distance <= ellStar_u)
```

and the far/error term

```text
eta_u^(-1) * (W*eta_u*ell_u)^(-1/3) * (JStar_{u,D})^3.
```

Formula (5.42), after propagation, has near indicator
`1(distance <= 6*ellStar_t)` and time/length power

```text
eta_u^(-1) * (eta_u/eta_t)^4 * (ell_u/ell_s)^5,
```

plus the same cubic `A_u^(-1/3)` row.  The paper absorbs the fourth-power
expansion by weakening the scale exponent from `-1/2` to `-1/3`.  The current
Lean surfaces intentionally stop before that absorption.

When the missing transition-support chain and the prefix-gradient/current-QV
producers are eventually available, the exact `crossPart_active_le_jointEvent`
coefficient should be normalized only once.  If

```text
Bfull(r) = (15*p/(8*sqrt r)) *
  (b(r)*sqrt(q(r)) + Eall(r)*rho^(1/(2*p))),
```

then the consumer shape is

```text
crossPart <= 2*p * momentPower * Bfull(r).
```

`Bfull` must not be multiplied by a second `2p`.  A later application of
`crossBudget_le_crossInt_model` must preserve this normalization and still
split the `r=0` endpoint before using its `u>0` hypothesis.

## Final dependency and satisfiability audit

- **Same event/sample:** T584, T586, and the recommended theorem all use the
  literal T579 `commonEvent` and the same `omega`; no event or sample is
  exchanged under a quantifier.
- **Closed endpoints:** the recommended running cap covers both `u=s_N` and
  `u=v_k`.  The later pointwise cross bound is only for `r>0`; `r=0` is an
  exact zero branch.  `k=0` is excluded from the running-cap theorem and is an
  exact zero/equal-endpoint branch later.
- **Moment order:** all Holder/cross norm arguments require `p>=1`; `p=0` is
  handled by the exact derivative-zero theorem.  The recommended support
  theorem itself is independent of `p`.
- **Regularity:** no future cross theorem is complete until the five literal
  measurability/integrability premises of
  `crossPart_active_le_jointEvent`, the global joint envelope, and the
  complement payment are discharged.  They must not be hidden in
  `NearCrossBridge`.
- **Noncircularity:** the recommended theorem uses only the smooth-prefix
  comparison, T479's deterministic field modulus/mesh, and T579's upstream
  common-event carrier.  It does not consume T584, T586, T591, a desired
  weighted moment, `hfamily`, `APrimeSlot'`, stopping, or BDG.
- **Satisfiability:** T579 witnesses a positive-length admissible first cell,
  an active positive prefix, a nonempty same common event, and positive target
  widened support.  Separate actual-smooth files witness genuine strict
  transitions.  No compiled theorem currently identifies those witnesses on
  the exact general-moving common event, so this report does not assert such
  an intersection.  The proposed implication is nevertheless the smallest
  honest support-local theorem; claiming the reverse weight implication would
  be both unjustified and stronger.
