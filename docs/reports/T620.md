# T620 — post-T615 deterministic drift-integration and consumer preflight

## Scope and verdict

### Independent-audit correction (supersedes the proposed T624 API below)

The sharp exponent ledger remains valid, but the proposed implementation is not dispatchable
as written.

1. The consumer's `htime` premise is a bound on the envelope
   `Qbd = profile + N^(-beta)`, not on the actual weighted norm `g`.  Since T615 proves
   `g <= Qbd`, a small integral of `g` cannot imply a small integral of `Qbd`.  The first
   public budget must therefore prove
   `2 * ∫ (profile + N^(-beta)) <= slotDrift / 2` (and its integrability); only afterward may
   it derive the actual-`g` corollary.
2. T615's `g` fixes `Step2.sigPM`, i.e. the `(+,-)` charge.  Its argument
   `a : LoopArg ... 2` is the output label, not a charge word.  No arbitrary-charge drift
   statement is selected here.
3. The proposed import surface is transitively downstream: both the slot arithmetic route
   and T615's current producer chain reach `APrimeModel` and `Flow.Step345Producer`.  A
   signature-preserving upstream core extraction must occur before this can be called a
   noncircular pre-Step-3 leaf.  T625 audits that extraction; T624 is withdrawn.
4. The residual numerical estimates use `c <= 1`, which is not a field of `Cond272Reg`.
   For private `Dims.exampleGrow`, an implementation must derive it eventually from
   `N^c <= A_t <= N` (at a nontrivial `N`) or avoid those reductions.

Accordingly, every later reference below to an arbitrary-charge half-slot theorem, to
`2*integral g` as the consumer-ready public target, or to the proposed imports as acyclic is
superseded by these corrections.  The paper/profile calculation itself is retained for the
future extracted fixed-`sigPM` envelope theorem.

This is a read-only mathematical/API audit of T615 against the project-local
paper, especially (5.40)–(5.41), and against the literal Lean consumer
`APrimeOneStep.drift_bound_of_envelopes`.  No Lean source or scheduler file was
changed.

**Verdict.**  T615 is a correct direct-integral producer.  Its exact
actual-smooth estimate can be integrated without passing through a pointwise
supremum.  The sharp Lean near/far/residual decomposition has strictly positive
exponent margins under the exponent `30` in `Cond272Reg`, provided the fixed
losses are chosen sufficiently small.  The smallest noncircular next Lean result
is an all-cell theorem saying that the actual-smooth drift contribution fits
**one half** of the literal `APrimeSlotArith.slotDrift`; the other half is left for
the cross term.  This is only a drift-slot theorem.

The theorem must remain fixed at `Gauss.Dims.exampleGrow` and `Step2.sigPM`.
It must keep

```text
deltaCap = deltaWeight + xi
```

literally distinct from `deltaWeight`, and it must quantify `p` and `beta`
before the eventual `N`.

## Direct deterministic integration

The only time substitution needed is the exact identity already formalized in
T340:

```text
du / eta_u = dR_u / (m R_u),      m = Im m^(E) > 0.
```

On the closed prefix one has

```text
1 <= R_u <= R_v <= R_t,
r_u^2 <= R_u,
A_v <= A_u,
R_u^30 <= A_u,
R_t^30 <= A_t,
A_u <= N,
W L <= N,
N^(5/8) <= W                         (exampleGrow, eventually).
```

Also, for any fixed positive bookkeeping loss `rho`, all fixed constants,
`xiK`, `cNear`, `cFar`, and the finitely many stretched-logarithmic factors can
be bounded by their allocated pieces of `N^rho`.  This allocation must be done
explicitly in Lean; `rho` below denotes the **total** allocation, not one copy
per factor.

Let

```text
eNear = zetaCtr + zetaSrc + rho,
eFlow = zetaCtr + tauG + 2 deltaCap + rho,
eFar  = zetaCtr + (3/2)(tauG + 2 deltaCap) + rho,
eQuad = 4 deltaCap + rho.
```

The non-negligible rows are then as follows.

| Literal Lean row | Power after `r_u^2 <= R_u` and integration | Required strict margin |
|---|---|---|
| near principal | `C N^eNear R_v^-2` | `eNear < deltaSlot/4` for the literal slot |
| `Jbar * flowDelta` | `C R_v^-2 N^eFlow R_t^(5/2) A_t^(-1/6)` | `eFlow/c + (5/2)/30 < 1/6` |
| `Jbar^(3/2) A_u^-1` | `C R_v^-2 N^eFar R_v^(9/2) A_v^-1` | `eFar/c + (9/2)/30 < 1` |
| `jSCap^2 eta_u^-1 A_u^-1` | `C R_v^-2 N^eQuad R_v^6 A_v^-1` | `eQuad/c + 6/30 < 1` |

The powers come directly from the literal profile:

- near: `R_u^-2 r_u^3 <= R_u^-1/2`, so its `dR/(mR)` integral is bounded;
- flow row: `R_u^-2 r_u Jbar <= C N^(tauG+2deltaCap) R_u^(5/2)`;
- sharp far row: `R_u^-2 r_u Jbar^(3/2) <=
  C N^((3/2)(tauG+2deltaCap)) R_u^(9/2)`;
- quadratic row: `R_u^-2 jSCap^2 <= C N^(4deltaCap)R_u^6`.

This preserves the endpoint factor `R_v^-2`; it is not replaced by a constant
before the exponent-30 calculation.

### Residual and floor rows

The remaining rows are genuinely negligible at `D >= 60`; none is discarded.
The following are the conservative exponent ledgers after using the exact
`exampleGrow` bandwidth bound.

1. The near residual uses
   `tailT(...,gap) <= 2 W^(-D)`.  After `W L <= N`, `A_u <= N`, and the same
   `R_u` integration, its bracket relative to `R_v^-2` is bounded by

   ```text
   C N^(eFlow + 2) W^(-D) R_v^(5/2).
   ```

   Since `eFlow < c/12 <= 1/12`, `R_v^(5/2) <= N^(1/12)`, and
   `W^(-D) <= N^(-5D/8)`, the decay margin at `D=60` is greater than
   `37.5 - (2 + 1/6) = 106/3`.

2. The `cFar Jbar W^-1` sibling has exponent at most
   `eFlow + 1/12 - 5/8 < -11/24`.

3. The far spatial leakage
   `Jbar^(3/2) L sqrt(W^(-D))/ell_u` has exponent at most

   ```text
   eFar + 1 + 3/20 - 5D/16.
   ```

   The sharp far margin gives `eFar < (17/20)c <= 17/20`; hence at `D=60`
   the decay margin is at least `67/4`.

4. The quadratic floor `jSCap^2 W L W^(-D)` has exponent at most

   ```text
   eQuad + 1 + 1/5 - 5D/8.
   ```

   The quadratic margin gives `eQuad < (4/5)c <= 4/5`; hence at `D=60`
   the decay margin is at least `71/2`.

The fixed-`D` logarithmic premise `(4D)^2 <= log W` required by
`gap_tail_le_two_floor` holds eventually.  No residual or floor term needs a
new probabilistic input.

## The known coarse-cubic failure

Using only the printed cubic far row in (5.41), with the stopped-scale heuristic
inserted but without the sharper Lean decomposition, gives the normalized row

```text
N^(6 delta + 3 tau + nu) A_v^(-1/3) R_v^8.
```

Exponent `30` would require

```text
(6 delta + 3 tau + nu)/c + 8/30 < 1/3.
```

This is not a consequence of the formerly used coarse choice `delta = c/20`.
Even with `nu=0` and `tau=delta/16`, the left side is

```text
99/320 + 4/15 = 553/960 > 1/3.
```

So the coarse printed cubic profile does not by itself prove the claimed sharp
budget.  No theorem in the next ticket may route through that monomial.  The
valid route is exactly the T598/T615 split above: the `flowDelta` row has
`(b,a)=(5/2,1/6)`, the `Jbar^(3/2)` row has `(9/2,1)`, and the actual Step2
quadratic row has `(6,1)`.

## Compatibility with `APrimeOneStep`

For a positive cell, set

```text
Adr(u) = T615.g(...,u),
Qbd(u) = T615.profile(...,deltaCap,...,u) + N^(-beta).
```

Then:

- `eventually_g_le_profile_add` is exactly the pointwise `hAbd` required by
  `APrimeOneStep.drift_bound_of_envelopes`;
- `intervalIntegrable_g` gives the drift integrability, while
  `intervalIntegrable_profile.add intervalIntegrable_const` gives envelope
  integrability;
- a future cross theorem may provide `Bcr`, `Cbd`, `hBbd`, and its half of the
  time budget;
- the deterministic calculation above supplies the drift half of `htime`.

Thus the API is a direct fit.  There is no need, and no valid route, to infer a
small pointwise supremum from the small time integral.  A continuous narrow
spike is the elementary counterexample to that inference.

The literal drift slot is

```text
APrimeSlotArith.slotDrift (mE E).im (N^(deltaSlot/8)) R_v.
```

`APrimeSlotArith.driftTerm_slot_ge` gives

```text
N^(deltaSlot/4) * (mE E).im^-1 / 4 <= slotDrift.
```

Hence `eNear < deltaSlot/4` absorbs all fixed constants after fixed `p` and
`beta`, and one may reserve one half of the literal slot for the drift.  This
does not estimate or assume the cross term.

For `k=0`, do not call the positive-cell pointwise theorem: use only
`cutNetPt_zero` and `intervalIntegral.integral_same`.  Both closed endpoints
remain present for every positive cell, including `u=s_N=0` when the moving
window starts at zero.
