# 并行 agent 协调手册（Claude Code 侧的经验，交 Cowork 做成 skill）

写于 2026-09-21。这一天用并行 agent 从 8448 条声明做到 10411 条、蓝图「未形式化」节点归零。
下面每一条都是**实际踩出来的**，带证据和出处；不写没验证过的通则。

---

## 一、这个项目最主要的缺陷不是错证明，是**空真**

**症状**：假设没人能满足 ⟹ 定理空真 ⟹ `lake build` 永远绿，`#print axioms` 也干净。
一天之内**九次**：

| # | 对象 | 病因 | 谁发现 |
|---|---|---|---|
| 1 | `MomentDuhamel.Hyp.EE` / `drift` | 字段无约束；`drift` 对所有矩阵量化 | T145 |
| 2 | `genLK` 多一个 `W⁻¹` | 钉死的 `F` 不是 (5.15) 的 `F` | T132b |
| 3 | `Hyp.integrable` 对 `u ∈ ℝ` 量化 | `u = 1` 处无包络 | T154 |
| 4 | `MinorGood` / `MinorGood'` | `∀ ω` 无事件限制，**对任何 `Ψ` 都假** | T164 → T172 |
| 5 | `FlucBound` 的 `B ≥ 64/65`、`MinorDiffGainUpTo` 同 | `ι` 无基数预算，`B ≍ Ψ` 不可达 | T171 / T176 |
| 6 | `TestFun`/`TestFunT` 对所有矩阵量化 | 非 Hermitian 处预解式无界 | T180 |
| 7 | `hMδ`/`hδC` 写成 `∀ p ∀ N` | 论文是「`p` 固定、`N → ∞`」，**整条端到端定理空真** | T188 |
| 8 | `hkerC` 的短窗口条件 | **在论文自己的网格上为假** | T192 → T195 |
| 9 | Step 6 的 `henvQ`/`henvG`/`henvLK`、`hmeas*`、`hintL1` | 时间 `v` 量化在**整个 `ℝ`** 而不是窗口；`ω = 0`、`E = 0`、`v ↑ 1` 处被积量有闭式且无界，**不存在任何包络** | T205 |

**处方（写进每一张实现单的 prompt）**：

> 动手证之前，先对每条新假设做**编译过的**可满足性检查：
> (a) 退化样本点——`ω = 0`、单个对角坐标拉大；
> (b) 退化参数——固定 `N` 令 `p → ∞`、窗口塌缩、`Λ = Φ = 0`；
> (c) **量词次序对照论文**；
> (d) 反向也要查：给出满足新形式的**正向见证**，以及旧形式的**反证**。
> 要**编译**，不接受散文论证。

**做得最好的几个样板**（可以直接抄）：
* `T169.MinorGoodLe.goodEvent` —— 把「结论非空洞」**反向证成定理**；
* `T197.satCutHyp` —— 完整实例，取在**临界标度 `J ≡ Θ`**（不是退化的 `0`），
  且让 `mesh_fine`（要网细）与 `card_le`（要网粗）这对**最易联合不可满足**的条件由同一见证满足；
* `T196` —— 显式造出非 Hermitian 且奇异的 `M`（原始预解式坍塌为 0），再证一致界**确实在该点取值**；
* `T175.cutChi_spec` —— 把整包规格合成一条**有居留性**的定理；
* `T177` —— 退化脚本喂进新接口后**正好卡在预算那一步**，带/不带预算的对照一并入库；
* `T181` —— **预先**证明 `Lemma514Premises` 不能删（删了在 `Λ = Φ = 0` 处塌）。

⚠ **第九例的教训是新的**：空真不一定出在随机层。T205 那条是**时间参数的量化范围**——假设写成 `∀ v : ℝ` 而证明里只用 `v ∈ [s_N, t_N]`。判别方法很便宜：**把每条假设的量化范围与它在证明里被使用的范围对一遍**，两者不符就是嫌疑。同一件事仓库里往往已经有窗口版（T150 的 `int1_gauss`），**形状对不上就是信号**。

**发现假陈述后**：用 `@[deprecated "RETIRED (Txxx): …"]`，**不要只写 docstring**。
docstring 挡不住下一个 agent——`MinorGood` 那支就是这么活了几周（T184）。

## 二、工单文本和 STATUS **会很快过时**，必须核不能读

并行之下，一张单派出去时它的描述可能已经不对了。**五次**：

* T180 的单说 `drift` 是唯一障碍——T163+T58 早已让它免费；
* T181 列 `hHol` 三个缺口——第一个 T116 早就有（`norm_gloop_sub_le`）；
* T158 说 Mathlib 的 `ContDiffBump` 可作见证——T175 发现它**没有导数界**，只能换构造；
* T178 断定 `hsym` 需要 (5.22) 第二项——T190 证明真正的问题是**割点选错**；
* T192 说短窗口是「真假设」——T195 证明它**在总装网格上为假**。

**处方**：
* 派单 prompt 里明写「**工单描述可能已过时，先按 STATUS 最新一节核**」，并列出自上次以来落地的相关票；
* 审计单要求「**用 grep 或编译探针核，不要读旧记载**」；
* 协调者**转派前重读工单全文（含审查段）**——我自己犯过一次相反的错（T132a 的转述）；
* 完成后**回写更正**：把被推翻的旧结论就地加注（`> ⚠ 后续更正（Txxx）：…`），别让后来人再撞。

## 三、只读审计的固有坑

**只读单编译的定理不会入库。** T195 编译了 7 条关键定理，提交是 docs-only，全仓 grep 零命中——
T193 查出来并**拒绝给它们挂 `\lean{}`**。
**处方**：只读单的 prompt 里写明「你的探针不入库，结论请写成可复现的路线，
并在报告里标明哪些是编译过但未入库的」；协调者在 STATUS 里也记一句。

## 四、按文件分工挡不住重复造轮子

`grep <name>` 查不到**概念相同、名字不同**的既有引理，而互不 import 的两个文件谁也看不见谁。
实际发生：`inv_sq_le_tailT` 两份（T155/T178）、`Lemma57.blkW` 与 `ChainExpand.eblkW`、
`fderiv2_comp_clm` 的一般版与 `EGDef` 的对角特例（T187 按概念才找到）。

**处方**：prompt 里写「**按名字 grep 之外，还要按概念 grep**」，并给出该主题下已有的关键词。

## 五、编译与构建的三个陷阱

1. **单文件 `lake env lean` 查不出跨文件重名。** 改了公共命名空间就得跑全量，
   或**逐个新名字全仓 grep**（T185 的 97 个名字、T196 的 56 个都是手动做的）。
2. **跨切面重构必须交全量绿构建**，单文件编译不算证据（`ThetaOp` 的 31 处引用、T149 的 15 条签名）。
3. **并发下 build 会被别人弄红**。prompt 里给出「其他 agent 正持有哪些文件」，
   并写明「若全量红在别人的文件上，按自己文件的 `Built`/`Replayed` 行判断，并在报告里说明」。

## 六、改共享文档的脚本

**我自己把 `docs/TASKS.md` 从 2695 行截成 4 行并提交推送了**——脚本写成 `s[:匹配点] + 新行`。

**处方**：
* **永远不要把文件写成它自己的前缀切片**；用 `splitlines()` + 插入 + 重新 join，或用带唯一锚点的 Edit；
* 改完**先断言行数/行计数没缩水再 `git add`**（`grep -c '^| T[0-9]'`）；
* **写完再 assert 太晚**——损坏已经在磁盘上了。

## 七、工具脚本本身要能自证

`scripts/blueprint_preview.py` 的正则遇到标题里的 `]` 会**静默丢掉整个节点**，
而「所有 N 个名字都存在」照样打绿——**三次**才被发现。
已修：标题惰性匹配，外加「环境个数 ≠ 节点个数就报错退出」。

**通则**：任何「检查器」都要有一条**总数守恒**的断言，否则它只会检查它看得见的那部分。

## 八、`decide` 不可伸缩时，把自检搬到 Lean 外面并说明

T168 实测 9 点树的无环性 `decide` 要 **85 秒**，放不进仓库。
改用 Python 穷举验证模型本身（`n ≤ 7` 的树数 1/3/11/45/197 对上 `|TSP n|`），
并在 Lean 里留一个小的可编译锚点（`figure_four`）。
T185 后来用**割证书 + 已有的 `sep_of_cut`** 彻底避开了 `decide`。

**通则**：模型/建模步是编译器唯一查不出的错，**必须另有独立自检**；
自检在 Lean 外面跑是可以的，但要写明**范围与理由**。

## 九、派单 prompt 的固定骨架

1. **身份与硬规则**：读 `CLAUDE.md`；无 `sorry`/`axiom`；不许发明 Mathlib 名字（先 grep/`#check`）；
   `#print axioms` 跑完删掉。
2. **本单要什么**，以及**已经有什么**（列出可直接复用的定理与文件，避免重造）。
3. **可能已过时的部分**，以及去哪里核最新状态。
4. **可写文件白名单 + 只读清单**（两者冲突时说明「以只读清单为准」——T196 遇到过）。
5. **纪律**：可满足性先行且要编译；不许伪造证明，**精确的否定结论是好结果**；
   不许弱化结论去收口；冻结签名加带撇版、旧的改成一行推论。
6. **验收条件**：最好是一条**探针**（「把结论裸应用喂进某个槽」），而不是「签名改好」。
7. **协议**：跑哪个编译命令、跑不跑 `lake build`、探针放 scratchpad、**不跑 git**、
   import 由协调者加、并发 agent 持有哪些文件。
8. **报告要求**：用中文；exit code 与审计行逐字给出；**没做的要说清楚短在哪、归谁**。

## 十、协调者自己的纪律

* **一单一 agent、file-disjoint**；同一个文件的续作交给**同一个 agent**（`Lemma57` 那条线）。
* **集成时逐条核**：import → 全量绿 → 蓝图 → paper-deltas → STATUS → TASKS → commit。
  提交信息写**结论和为什么**，不写流水账。
* **每次集成都要问：这次的结论是否推翻了我之前向 Jun 转述过的东西？** 今天推翻了五次，
  每次都得当面更正（`hsym`、单张量归约、短窗口、`ContDiffBump`、裸 `Cond272`）。
* **路由决策**（谁做、放哪个文件、怎么解依赖环）自己定，不必请示；
  **改范围、论文措辞、接口形状**写进 STATUS 的「待 Jun 定夺」，**不在对话里问**。
* **不写工单**（Cowork 的活），但**发现无主的活要写进 STATUS 点名**，
  并且**点名到字段级**——T182 那句「归包络那条线」没有收件人，结果那条线根本没有单。

## 十一、最值得保留的产出形态：**带证明的否定结论**

今天改变计划的几乎全是否定结论，而且都编译成了定理：

* `LDENetClose` **按字面不可证**（等价于一个为假的下界）——T148；
* `MinorGood` 对**任何** `Ψ` 都假——T172；
* `MomentHyp.step` 在冻结形状下**不可证**（两条阻塞各一条定理）——T132c；
* `hG` 按字面**推不出来**（一致界只能给 `W·L·Λ`）——T189；
* `(+,+)` 的「免自举」捷径**不收缩**——T132c；
* 裸 `Cond272` **不够**（`A_t = 1` 可取到）——T186，**反转了一次裁定**。

**所以 prompt 里要明说**：证不出来时，**精确报告短在哪个因子、差多少**，
比强行收口有用得多；能把「不可证」编译成定理最好。
